1. 개요#

1.1 한 줄 소개#

작업하는 동안 화면 구석(기본 우하단)에 떠 있는 작은 창에서 일정 시간마다 야생 포켓몬이 나타나고, 과녁을 클릭하는 짧은 전투로 포켓몬을 잡아 모으고, 잡은 포켓몬을 원정에 보내 아이템과 재화를 얻는 방치형 데스크탑 컴패니언.

1.2 핵심 경험#

  1. 방해하지 않는다 — 평소에는 작고 조용하다. 알림 팝업 없이 소리로만 알린다.
  2. 가끔 반갑다 — 일정 시간마다 포켓몬이 나타나고, 수십 초짜리 클릭 전투로 잡는다.
  3. 모으는 재미가 쌓인다 — 플레이어 레벨과 도감이 늘면서 새 지역이 열리고, 새 포켓몬과 전설의 포켓몬을 만난다.
  4. 놀리지 않는다 — 잡은 포켓몬은 원정을 보내 시간만 지나면 아이템을 벌어 온다(앱을 꺼 둔 동안에도 진행). 중복 개체는 박사에게 보내 성장 자원으로 바꾼다.

1.3 두 가지 활동의 구분#

const BASE_SIZE := Vector2i(320, 120)

    var usable: Rect2i = DisplayServer.screen_get_usable_rect(screen)  # 작업표시줄 제외

    get_window().always_on_top = enabled
    for w in _popup_windows: w.always_on_top = enabled
    Settings.set_value(&"always_on_top", enabled)

    var win := get_window()
    var bottom_left := Vector2i(win.position.x, win.position.y + win.size.y)

    _clamp_into_screen()

4.3 인카운터 전투 (과녁 클릭 포획)#

인카운터는 짧은 시간을 소모하는 전투다. Cornerpond처럼 나타나는 과녁을 클릭해 게이지를 채우면 포획한다.

┌────────────────────────────────────────┐
│        ◎              (과녁)             │
│            [포켓몬 80×80]      ◎         │   과녁: 무작위 위치에 나타나 점점 줄어듦
│   ◎        ═══받침═══                    │   클릭 성공 → 게이지 증가
│ [■■■■■■□□□□] 12s                         │   놓침/소멸 → 게이지 감소
└────────────────────────────────────────┘
  1. 출현한 포켓몬을 클릭하면 전투 시작. 이 시점에 선택된 볼 1개 소모(몬스터볼은 소모 없음).
  2. 과녁이 포켓몬 주변 무작위 위치에 나타나 일정 시간 동안 줄어들다 사라진다. 동시에 최대 2~3개.
  3. 과녁 클릭: 게이지 +fill. 중심(작은 원)에 가까울수록 추가 보너스.
  4. 과녁 소멸(놓침) 또는 빈 곳 클릭: 게이지 −penalty. 게이지는 시간이 지나면서 조금씩 줄어든다.
  5. 제한 시간(10초, v0.74 — v0.55~0.73 12초, 그 전 20초) 안에 게이지가 가득 차면 포획 성공(볼 던지기 연출). 실패하면 도망.
  6. 포획 연출 (v0.50, assets/scenes/main/capture_anim.gd): 게이지가 가득 차면 과녁·게이지를 치우고(왼쪽 안내 문구 "가랏! <볼 이름>!") —

① 전투 칸 왼쪽 아래에서 이번 전투에 쓴 볼이 돌며(회전 8프레임) 포물선으로 날아가(0.6초) ② 포켓몬 위에서 열리고, 포켓몬이 하얗게 빛나며 작아져 볼 속으로 빨려 들어간다(0.45초) ③ 볼이 닫혀 발판에 떨어져 한 번 튄 뒤 ④ 3번 흔들리고(볼 아래를 축으로 좌우 22°) ⑤ 볼에서 별 3개가 튀어 나와 날아가며(v0.73: 별마다 무작위 방향·속도로 돌며, 11×11 다섯 꼭지 별 — v0.53에서 7×7의 1.5배, 하얀색에 가까운 연노란색, 테두리·밝은 점 없음. 볼 꼭대기에서 왼쪽 위·위·오른쪽 위로 튀어 나가 중력으로 조금 휘며 0.85초 동안 날아가고, 절반쯤부터 서서히 사라짐. v0.51~0.52 — 색이 다른 포켓몬 등장 반짝임과 다른 효과) 잡힌다 → 포획 정보 창. 전체 약 4.5초.

  • 흔들리다 빠져나오는 실패는 없다(게이지를 채우면 언제나 잡힘). 볼은 다음 대기 화면이 될 때까지 발판 위에 남는다.
  • 볼 그림: Poke Balls 시트의 볼 종류별 줄(tools/make_ball_frames.py → assets/generated/ui/balls/<볼 id>.png, 16×24 칸 10개: 회전 0~7(0 = 똑바로 선 모습, 놓인 볼·흔들림에 씀), 8 납작(바닥에 부딪힌 모습, 쓰지 않음 — v0.50에서 이걸 써서 볼이 가로로 찌그러져 보였음), 열림 9). 몬스터볼·슈퍼볼·하이퍼볼·마스터볼.
  • 효과음은 아직 없다(던지기·흔들림 소리를 넣으면 연결 가능). 포획 효과음은 기존대로 포획 시점에 난다.

난이도 공식 (초안, formulas.gd)

difficulty  = clamp((1 - catch_rate / 255.0) * 0.8 + (level / 100.0) * 0.2, 0, 1)
              (+ 0.15 전설) (+ 출현 표의 추가 난이도 difficulty_bonus, v0.76 — 동굴 라프라스 0.2)
target_life = lerp(1.6, 0.55, 0.6·d + 0.4·d²)   # 초. 어려운 쪽에서 더 급격히 빨라짐 (M4 조정)
target_size = lerp(17, 9, difficulty)            # 기준 해상도 px 반지름 (M4: 약간 작게)
fill        = 0.12 * ball.catch_modifier * region.capture_fill * (몬스터볼이면 region.poke_ball_fill)   # 게이지 비율 (v0.63: 지역 배율, v0.92: 몬스터볼 추가 배율)
penalty     = lerp(0.04, 0.10, difficulty)
decay/sec   = lerp(0.01, 0.04, difficulty)
  • 볼 배율: 몬스터볼 1.0, 슈퍼볼 1.5, 하이퍼볼 2.0.
  • 지역 배율 capture_fill (v0.63): 후반 지역일수록 과녁 한 번에 덜 찬다 — 초원 1.0 · 숲 0.95 · 물가 0.9 · 동굴 0.85 · 발전소 0.8 · 화산 0.75 · 유령탑 0.72 · 설산 0.68 · 깊은 동굴 0.65 (tools/source/regions_gen1.json, RegionData.capture_fill, EncounterManager.region_capture_fill()). 깊은 동굴에서 몬스터볼은 초원보다 약 1.5배 많이 맞혀야 하고, 하이퍼볼(×2 → 1.3)이면 초원 몬스터볼보다 잘 찬다. 엔트리 보너스·긴장감 특성과 곱해진다.
  • 몬스터볼 추가 배율 poke_ball_fill (v0.92): 발전소부터 뒤로 갈수록 몬스터볼로는 잡기 어렵게 몬스터볼에만 곱하는 배율 — 발전소 ×0.9 · 화산 ×0.8 · 유령탑 ×0.7 · 설산 ×0.6 · 깊은 동굴 ×0.5(초원~동굴은 1.0). 슈퍼볼·하이퍼볼에는 적용하지 않는다(tools/source/regions_gen1.json, RegionData.poke_ball_fill, EncounterManager.region_capture_fill(ball)). 몬스터볼의 실제 배율(지역 배율 × 추가 배율)은 발전소 .72 → 화산 .60 → 유령탑 .50 → 설산 .41 → 깊은 동굴 .33(초원 1.0). 깊은 동굴에서 슈퍼볼(×1.5 → 0.98)은 초원 몬스터볼과 비슷하고, 하이퍼볼(×2 → 1.3)은 더 잘 찬다. 쉬운 포켓몬(큰 과녁·느린 게이지 감소)은 몬스터볼로도 잡히지만 어려운 포켓몬은 사실상 슈퍼볼 이상이 필요하다. 지역 화면에는 따로 안내하지 않는다(전투 게이지로 체감).
  • 과녁은 포켓몬을 가리지 않는다: 포켓몬 스프라이트의 실제 그림 영역(투명 여백 제외)과 게이지 줄을 피해서 생성한다(과녁 원 전체가 영역 밖).
  • 창 배율과 관계없이 같은 난이도가 되도록 기준 해상도 좌표로 계산한다.
  • 엔트리 보너스 (v0.26, 4.13): 엔트리의 능력치에 따라 게이지 증가량·과녁 유지 시간·제한 시간이 늘고 감점·게이지 감소가 줄어든다(각 최대 25%).
  • 볼 선택: HUD의 볼 아이콘 클릭으로 순환 선택, 선택은 저장.
  • 연출 리소스: 받침은 Battle Bases 시트, 볼은 Poke Balls 시트 사용(7.4).

4.4 지역과 해금#

  • 해금된 지역 중 하나를 현재 지역으로 선택한다. 인카운터는 현재 지역 테이블을 쓴다.
  • 지역마다 배경 장면과 전투 받침이 다르다.
  • 해금 조건은 아래 조건 타입의 조합(AND)으로 데이터에 정의한다.
조건 타입예시
player_level플레이어 레벨 10 이상
dex_caught_count도감 포획 종류 수 20 이상
species_caught특정 종 포획
type_caught_count물 타입 5종 이상 포획
region_unlocked이전 지역 해금
  • 조건 확인 시점: 포획·진화·레벨업·원정 보상 수령 직후, 앱 시작 시.
  • 잠긴 지역은 조건과 진행도를 보여준다.

M5 구현 메모

  • 지역 정의는 tools/source/regions_gen1.json(출현 표: 도감번호, 가중치, 레벨 범위, 필요 플레이어 Lv) → tools/json_to_regions.gd → assets/data/regions/*.tres. 지역별 임시 배경색(하늘·땅)도 여기서 정한다.
  • 해금 판정은 UnlockManager: 포획·플레이어 레벨업·앱 시작 때 확인하고, 새로 해금되면 메인 창에 "새 지역 해금: ○○!"와 알림음.
  • 해금 알림 팝업 (v0.25): 새 지역이 열리면 "새 지역 해금" 팝업(확인 버튼 하나, ConfirmPanel.notify)에 "새로운 지역이 해금되었다! / 지역 이름 / 지역 버튼에서 이동할 수 있다."를 띄운다. 인카운터 대기 중에만 띄우고(전투·결과 표시 중이면 끝난 뒤), 한꺼번에 여러 지역이 열리면 한 팝업에 모은다. 지역 이름은 그 지역 대표 타입(main_types 첫 번째)의 타입 색으로 칠한다(v0.89, UiUtil.region_bbcode. 초원 노말·숲 벌레·물가 물·동굴과 깊은 동굴 바위·발전소 전기·화산 불꽃·유령탑 고스트·설산 얼음). "확인"을 눌러야 사라진다(전투가 시작돼 닫혀도 끝난 뒤 다시 뜬다).
  • 지역 선택은 버튼 줄의 "지역" 패널. 잠긴 지역은 조건별 진행도(예: 도감 10종 포획 (4/10))를 보여준다. 지역을 바꾸면 다음 인카운터부터 적용.
  • 데이터 검증 테스트: 모든 비전설 종이 어떤 지역 표에 있거나 진화로 얻을 수 있는지, 각 지역의 해금 조건을 앞선 지역(+진화)만으로 달성할 수 있는지(막힘 방지).

4.5 전설의 포켓몬#

  • 1세대 대상: 프리져, 썬더, 파이어, 뮤츠, 뮤(환상).
  • 일반 출현 테이블에 넣지 않는다. 조건을 만족하면 인카운터마다 낮은 확률(3%, M10. 초안 1%)로 등장.
  • 중복 포획 가능. 잡은 뒤에도 같은 확률로 다시 나온다.
  • 조건은 자동 생성한다(tools/generate_legendary_conditions.gd).
for legend in GameData.legendaries():            # is_legendary 또는 is_mythical
    main_type  = legend.types[0]
    conditions = [
      {type: "player_level",      value: 25 + 3 * legend_index},          # 최대 37 (상한 40 이내)
      {type: "type_caught_count", type_id: main_type, value: ceil(같은 타입 비전설 종 수 * 0.6)},
      {type: "dex_caught_count",  value: floor(비전설 종 수 * 비율)},     # 비율: 일반 0.7, 뮤츠 0.9, 환상 1.0
    ]
    region_ids = main_type이 대표 타입인 지역 (없으면 모든 지역)

다른 세대를 추가해도 같은 규칙으로 조건이 만들어진다. 결과는 .tres로 저장되고 손으로 고칠 수 있다.

  • 전투 난이도 +0.15.

4.6 특성 (팰월드식 패시브)#

  • 특성은 패시브다. 특성마다 발동하는 곳이 정해져 있다: 원정 특성은 그 포켓몬이 원정 파티에 있을 때, 전투 특성은 그 포켓몬이 엔트리(4.13)일 때 발동한다. (v0.26. 이전에는 원정에만 영향)
  • 모든 포켓몬은 포획 시 특성이 무작위로 생성될 수 있다(팰월드의 개체별 패시브처럼). 같은 종이라도 개체마다 특성이 달라서, 중복 개체를 골라 키우는 이유가 된다.
  • 전설·환상 포켓몬은 무작위 특성에 더해 고정 특성 "전설" 을 항상 가진다. 색이 다른 포켓몬(4.2, P2)은 고정 특성 "색이다른" 을 가진다.
v0.28 특성 개편 — 구현됨. 아래 "개편 특성 목록"대로 동작한다. 개편 원칙:
1. M7에서 만든 기존 특성(튼튼함·힘셈·길잡이 등 16종)은 모두 삭제한다.
2. 공격·특공 같은 개별 능력치를 바꾸는 특성은 만들지 않는다(stat_mult 폐지).
3. 전투력을 바꾸는 효과는 자신에게만 적용한다(파티 전원의 전투력을 바꾸는 특성은 없다, v0.26).
4. 실제 포켓몬 특성의 이름을 쓴다(고정 특성 "전설"·"색이다른"은 예외).

데이터: tools/source/traits.json(수치는 여기만 고친다) → tools/json_to_traits_expeditions.gd → assets/data/traits/*.tres. 계산: 원정 ExpeditionLogic(pokemon_power·party_mods·roll_rewards), 전투 BattleTraits(collect·roll_after_battle·buff_lines).
옛 특성(튼튼함·길잡이 등)이 있던 세이브는 불러올 때 그 특성을 지운다(지금 데이터에 없는 특성 id 제거). 고정 특성 "전설"은 id(legend)가 같아 그대로 남는다.
제안값은 모두 채택(v0.28): 전설 보상 ×1.3, 타입 조건 전투력 ×1.2, 악취 = 전투 특성, 꿀모으기 레벨×2원, 픽업 15%, 출현 ×1.5, 중첩X·상한. 바꾸려면 JSON 만 고친다.

밸런스 검토 (v0.26)

  1. 전투력 특성은 이제 모두 자신에게만 적용된다. 최대 인원이 없어서 전투력 특성은 사실상 "필요 인원을 몇 마리 줄여 주는" 효과이고 후반에는 영향이 작다(v0.25 검토와 같음). 타입 조건 특성(맹화 등)은 자신만 바꾸게 되면서 ×1.1 → ×1.2로 올렸다. 무작위로 붙으므로 그 타입이 아닌 포켓몬에 붙으면 효과가 없다(예: 피카츄의 맹화) → 그런 개체는 박사에게 보내는 후보가 된다.
  2. 원정 효과(시간·보상)는 같은 특성끼리 중첩X, 다른 특성끼리 곱하고 상한을 둔다: 원정 시간 ×0.6~×1.3, 원정 보상(요구치 초과 보너스 ×1.5 포함) 최대 ×2.0.
  3. 전설의 보상 ×1.5 → ×1.3 제안(v0.25 검토와 같음: 후반 원정에 거의 항상 붙고, 요구치 초과 보너스와 곱하면 ×2.25).
  4. 엔트리 3칸이라 전투 특성은 골라 쓰는 재미가 있다. 엔트리로 정한 포켓몬은 원정에 못 가므로, 좋은 원정 특성을 가진 포켓몬과 전투 특성을 가진 포켓몬을 나눠 쓰게 된다. 단, 엔트리는 능력치 보너스(4.13)도 주므로 "강한 포켓몬"과 "전투 특성을 가진 포켓몬" 사이에서도 고민이 생긴다.
  5. 꿀모으기 수치 주의. 초원은 인카운터가 30초~2분마다라 시간당 전투가 30~40번까지 나온다. 야생 레벨 × 2원이면 초원(Lv2~8)에서 시간당 약 300~600원, 깊은 동굴(Lv40~60, 4~9분 간격)에서 시간당 약 900~1,500원. 8시간 원정 재화(2,400~4,000원)와 비교하면 꽤 크다 → 구현 후 시뮬레이터로 보고 × 1원까지 낮출 수 있다.
  6. 픽업 15%: 시간당 전투 30번이면 아이템 4~5개. 대부분 몬스터볼·슈퍼볼로 두고, 금구슬은 낮은 가중치(예: 5%)로 둔다.
  7. 출현 ↑ ×1.5: 예를 들어 숲에서 풀 타입 가중치 합이 전체의 약 30%라면 약 39%로 오른다. 원하는 종을 노릴 수 있지만 확정은 아니다. 엔트리 3칸에 같은 특성 3개를 넣어도 중첩X라서 ×1.5 그대로.
  8. 의기양양(레벨 +2): 포획 난이도에서 레벨 비중은 20%라 체감 난이도는 거의 같고, 포획 경험치는 레벨당 2 오른다(4.1). 지역 최고 레벨 제한이 있어 후반 지역에서는 의미가 작다.
  9. 볼줍기: v0.56부터 성공·실패 상관없이 확률로 볼을 돌려준다. v0.81에서 30% → 15%(슈퍼볼·하이퍼볼을 평균 약 15% 아낌). 발동하면 왼쪽 아래 알림 "볼줍기 +슈퍼볼".
  10. 부정 전투 특성(긴장감·악취): 엔트리에서 빼면 끝이라 부담이 작다. 부정 특성은 대부분 "그 자리에 안 쓰면 된다"이므로 이 정도가 적당하다.

4.7 보유 포켓몬#

4.7.1 능력치#

종족값·레벨·개체치(v0.55)로 계산한다. 노력치는 없다.

hp   = floor((2 * base.hp + iv.hp) * level / 100) + level + 10
기타 = floor((2 * base.X  + iv.X ) * level / 100) + 5
최종 = floor(능력치 * Π(특성의 stat_mult))   # 특성 개편(4.6) 후 stat_mult 는 없어진다. 지닌 물건 없음(v0.24 폐기)

개체치 (v0.55): 잡을 때 능력치 6종마다 0~31을 고르게 뽑아 개체에 저장한다(ivs). 같은 종·같은 레벨이어도 능력치가 다르다. 진화해도 그대로.

  • 보관함 표시: 31 = 값 옆 ★★, 25~30 = ★, 0~9 = 값이 하늘색, 10~24 = 표시 없음.
  • v0.55 이전 세이브의 개체는 불러올 때 개체치를 새로 뽑는다(범위 밖 값은 0~31로 자름).
  • 엔트리 보너스 기준(4.13)은 개체치 31(종족값 80·Lv80) → 최대 보너스에는 개체치도 높아야 한다(개체치 노가다). 원정 전투력도 개체치가 반영된 능력치를 쓴다.

exp_to_next(L)  = 50 + 10 * L + floor(L * L / 2)
total_exp(L)    = Σ exp_to_next(1 .. L-1)        # Lv1에서 Lv L까지 필요한 누적 경험치
레벨다음 레벨까지누적(Lv1부터)
5112약 320
10200약 1,000
20450약 4,100
30800약 10,100
501,800약 34,900
100—약 218,600
위 누적값은 공식으로 계산해 formulas.gd의 테스트로 고정한다. 표는 참고용이다.

4.8.2 박사에게 보내기#

  • 포켓몬 GO 방식. 놓아주기 기능은 박사에게 보내기로 대체한다.
  • 개체를 보내면 사라지고 보낸 포켓몬의 레벨에 비례한 경험사탕을 받는다. 별도 자원은 없다.
  • 지급량 계산 (자동, formulas.gd):
value   = 100 + floor(total_exp(level) * 0.18)   # 경험치 환산값: 키운 경험치의 18% + 기본 100 (M10, 초안 25%)
M 개수  = floor(value / 800)
S 개수  = round((value - M * 800) / 100)         # 최소 1개 보장
보낸 레벨환산값받는 사탕
5약 180S×2
10약 350S×4
20약 1,130M×1, S×3
30약 2,620M×3, S×2
50약 8,830M×11
100약 54,750M×68, S×4
  • 18%라서 같은 경험치를 다시 쌓으려면 손해 → 키운 개체를 쉽게 보내지 않게 하면서, 막 잡은 중복 개체(저레벨)는 꾸준히 사탕이 된다. 비율(0.18)과 기본값(100)은 밸런스 상수. 위 표는 초안(25%) 기준이며 현재 값: Lv5 → S2, Lv20 → M1, Lv50 → M7 S8.
  • 단일/일괄 보내기 지원(종별 "1마리만 남기고 보내기", 특성 없는 개체만 보내기 필터).
  • 원정 중이거나 즐겨찾기한 개체는 보낼 수 없다.
  • 특성 캡슐 (v0.79, 플레이어 Lv12부터): 특성이 있는 개체를 한 마리씩 보내면(중복 보내기로는 안 나옴) 그 개체의 일반·희귀 특성 중 하나를 고르게 고른 뒤 일반 25% / 희귀 10% 로 "특성 캡슐 (그 특성)"을 준다. 부정 특성·고정 특성(전설·색이다른)은 담기지 않는다. 확인 창에 특성별 확률(예: "특성 캡슐을 얻을 수도 있다: 픽업 10%", 담길 특성이 2개면 각각 절반), 얻으면 결과 문구 다음 줄에 "특성 캡슐 (픽업)을(를) 얻었다!"(아이템 획득 소리). 확률은 ProfessorManager.CAPSULE_CHANCE.
  • 캡슐 쓰기: 보관함에서 포켓몬을 고르면 특성 상자 아래 "특성 캡슐" 버튼(캡슐이 있을 때) → 오른쪽 칸에 가진 캡슐 목록(특성 이름 ×개수, 툴팁 = 특성 설명, 쓸 수 없으면 비활성 + 이유) → 확인 창 → 확정으로 붙는다. 무작위 특성(고정 특성 제외)이 3개 미만이면 추가, 3개면 바꿀 특성을 고른다. "같이 안 붙음" 특성이 있으면 그 자리에서 바뀐다(확인 창에 "대신 ○○ 특성은 없어진다"). 이미 가진 특성이거나 원정 중이면 못 쓴다.
  • 깜빡열매 (v0.79): 부정 특성이 있는 개체에만 "깜빡열매" 버튼. 부정 특성이 하나면 바로 확인 창, 여러 개면 지울 특성을 고른다.

M8 구현 메모 (보내기)

  • ProfessorManager.transfer(uids): 하나라도 보낼 수 없으면(원정 중·즐겨찾기) 아무것도 보내지 않는다. 보낸 개체의 도감 기록은 남는다.
  • 중복 보내기(보관함 제목 줄): 종마다 가장 좋은 1마리(레벨 높은 순 → 특성 많은 순)를 남기고 나머지를 보낸다. 즐겨찾기·원정 중·특성 있는 개체는 남긴다. 보내기 전에 마릿수와 받을 사탕을 확인 창으로 보여준다.
  • 즐겨찾기 (v0.71, 잠금을 대신함): 보관함 오른쪽 정보 칸의 오른쪽 위 끝에 붙은 2배 크기 별(★) 버튼(v0.72, 처음엔 이름·성별 바로 오른쪽. 켜면 금색, 끄면 흐린 회색). 즐겨찾기한 개체는 목록에서 금색 + 이름 앞 ★, 보낼 수 없다. 파티·원정 목록에서 맨 위(party_panel.gd·expedition_panel.gd 정렬). 예전 세이브의 잠금은 즐겨찾기로 옮긴다.

진화 취소

  • 레벨 진화 연출 중 "취소" 버튼으로 멈출 수 있다(본가의 B 버튼처럼). "넘기기"(v0.83)를 누르면 깜빡임을 건너뛰고 바로 진화한다(진화의 돌도 같음). 두 버튼은 가운데에 나란히(6.2 팝업 규칙).
  • 취소하면 다음 레벨업 때 다시 진화를 시도한다.
  • 취소한 개체는 상세 화면에 "진화하기" 버튼이 생긴다(Lv100이라 더 레벨업할 수 없는 경우 등에 대비).
  • 일괄 처리 중(사탕 여러 번 사용, 원정 귀환 등) 여러 마리가 진화하면 연출을 순서대로 하나씩 보여준다.
  • 원정 중 진화 레벨에 도달하면 귀환 시 진화 연출.
  • 진화하면 도감에 새 종이 포획으로 등록되고 플레이어 경험치를 얻는다. 특성·성별·색이 다른 개체 여부는 유지.

  • 레벨 진화: 경험사탕·원정 보상 등으로 진화 레벨에 도달하는 순간 대기열에 들어가 연출이 시작된다. 취소하면 다음 레벨업 때 다시 시도하고, 그 전에도 보관함의 "진화하기" 버튼으로 다시 진화할 수 있다(Lv100이거나 앱을 껐다 켠 경우 대비).

전투력 계산 (초안)

개체 전투력 = (최종 HP + 공격 + 방어 + 특공 + 특방 + 스피드) * type_bonus
  최종 능력치 = 4.7.1 (stat_mult 특성 포함)
  × 자신의 power_mult, type_power_mult 특성   # 특성 개편(4.6) 후에도 유지 (+ ignore_weak_type, weak_type_mult)
  type_bonus = 원정지 추천 타입과 일치하면 1.25 (복합 타입은 하나만 일치해도) / 불리 타입이면 0.85

파티 전투력 = Σ 개체 전투력 * party_bonus
  party_bonus = 1.0 + (서로 다른 타입 수 ≥ 4 ? 0.05 : 0)   # 인원 보너스는 v0.24에서 없앰 (인원 제한이 없으므로)
              × 파티의 party_power_mult 특성   # 개편 후: 타입별 배율(party_type_power_mult), 같은 특성은 중첩X

소요 시간 = 기본 시간 × 파티의 duration_mult 특성 (하한 있음)
보상     = 추첨 횟수 + reward_rolls_add, 재화 × currency_mult, 경험치 × exp_mult

결과

  • ratio = 파티 전투력 / 요구 전투력
  • ratio ≥ 1.0: 성공. 초과분에 비례해 보상 보너스(상한 1.5배).
  • 0.7 ≤ ratio < 1.0: 성공 확률 (ratio - 0.7) / 0.3. 실패 시 보상 30%.
  • ratio < 0.7: 출발 불가(UI에서 막음).
  • 공통: 참여 포켓몬 경험치, 플레이어 경험치.

보상

  • 원정지별 보상 테이블(아이템 ID, 수량 범위, 가중치)에서 N회 추첨 + 재화.
  • 보상 종류: 재화, 볼, 경험사탕, 진화의 돌. 열쇠 아이템·지닌 물건은 없다.
  • 원정지마다 주는 진화의 돌을 다르게 한다(화산 → 불꽃의 돌).

4.13 엔트리 (파티) — v0.26#

엔트리는 인카운터 전투에 함께 나가는 포켓몬이다. 최대 3마리. 엔트리의 능력치가 과녁 전투를 돕고, 엔트리의 특성 중 "전투" 특성이 발동한다(4.6, 특성 개편 후).

7. 데이터 설계와 세대 확장#

7.1 원칙#

  • 세대는 데이터로만 추가한다. 코드에 "151", "1세대" 같은 상수를 넣지 않는다.
  • 포켓몬 기본 키는 전국도감 번호.
  • 세대별 데이터는 폴더로 분리하고, 시작 시 레지스트리가 폴더를 스캔해 로드한다.
  • 활성 세대는 데이터로 제어한다(enabled_generations: [1]). 2세대 스프라이트 시트가 이미 있으므로, 2세대 추가 시 시트 영역 정의 + CSV만 추가하면 되는지를 확장성 검증 기준으로 삼는다.
  • 전설 조건 생성, 도감 크기, 타입 목록은 활성 세대 데이터에서 계산한다.

8.4 계층과 패턴#

계층위치하는 일
데이터scripts/data + assets/data/**/*.tresResource 정의와 값. 로직은 넣지 않는다
로직scripts/logic상태 없는 static 순수 함수(계산·판정·추첨). RNG는 인자로 받는다
매니저scripts/autoload상태를 갖고, 로직을 호출하고, EventBus로 알리고, 세이브한다
화면scenes매니저 메서드를 호출하고, 시그널을 받아 화면만 갱신한다. 연출·입력 처리
  • 쓰는 패턴: 싱글톤(오토로드), 옵서버(EventBus), 데이터 주도 Resource, 순수 함수 계산, 연출 상태 머신.
  • 화면은 매니저의 상태 값을 직접 대입하지 않고 매니저 메서드를 부른다.
  • 여러 곳이 알아야 하는 사건은 EventBus로 보내고, 보내는 쪽은 매니저다. 부모·자식 씬 사이에서만 오가는 신호는 그 노드의 signal로 둔다.
  • 새 기능의 위치: 저장할 상태는 기존 매니저에 넣는다. 맡을 매니저가 없을 때만 새 오토로드를 만들고 8.1 표에 먼저 적는다. 계산·판정은 scripts/logic, 연출·입력은 씬에 둔다.
  • 긴 파일(companion.gd, storage_panel.gd)은 새 기능이 다른 역할을 더할 때 그 부분만 별도 씬·스크립트로 떼어 낸다.

8.5 코드 컨벤션#

  • 모든 var, 인자, 반환값에 정적 타입을 붙인다. JSON 파싱 결과처럼 타입이 정해지지 않은 값은 : Variant로 적는다.
  • 이름: 파일·함수·변수 snake_case, 클래스 PascalCase, 상수 UPPER_SNAKE, 비공개 멤버 _ 접두사, id는 &"..."(StringName).
  • class_name은 데이터·로직 스크립트에 붙이고, 오토로드에는 붙이지 않는다.
  • 주석은 한국어로 쓴다. 공개 함수에는 ## 문서 주석을 달고 관련 절을 (기획서 x.y)로 적는다.
  • 밸런스 수치는 Formulas 상수나 Resource에 두고, 바꾸면 기획서의 해당 절도 함께 고친다.

8.6 구현 범위와 테스트#

  • 기획서에 적힌 범위만 구현하고, 우선순위 표기(P0/P1/P2)를 따른다. 기획서에 없는 수치·동작이 필요하면 추천안과 함께 사용자에게 묻고, 정해지면 기획서에 먼저 적는다. 아직 못 정한 것은 13장에 올린다.
  • 로직·매니저를 바꾸면 gdUnit 테스트를 추가하거나 고친다. 확률은 RNG 시드를 고정해 확인한다.
  • 화면을 바꾸면 컴파일 테스트와 실제 화면 캡처로 확인한다.

  • 저작권/상표: 포켓몬의 이름·이미지는 닌텐도/게임프리크/크리처스/(주)포켓몬의 IP이고, assets/sprites의 HGSS 시트는 게임에서 추출한 저작물이다(시트에도 저작권 표기가 있음). 비상업 목적이라도 공개 배포하면 권리자가 삭제를 요청할 수 있다.
    • 지인 공개: 공개 링크가 아닌 개별 전달 수준으로 한정 권장.
    • 포트폴리오: 영상/GIF와 소스 코드 위주로 공개하고, 공개 저장소에는 assets/sprites/와 assets/generated/를 넣지 않는다(.gitignore). 스프라이트가 없을 때는 플레이스홀더로 실행되도록 폴백을 둔다.
    • 폰트 pokemon-dppt.ttf도 출처와 라이선스를 확인한다.
  • always on top과 전체화면 앱: 전체화면 게임/영상 위에 뜨는 문제 → v0.77에서 "전체화면 앱 실행 중 숨기기"로 해결(3.1).
  • 드래그 API: Window.start_drag()가 4.7.2에 없거나 다르게 동작하면 수동 드래그로 대체.
  • 아틀라스 자동 검출 실패: 블록 배치가 불규칙해 자동 검출이 일부 틀릴 수 있다 → JSON 수동 수정 + 미리보기 시트로 확인.
  • 시계 조작: 원정 시간은 시스템 시계 기준. 개인용이므로 음수 경과만 막는다.
  • Godot 4.7.2 API 차이: 문서의 API 이름은 4.3~4.x 기준. 구현 전에 확인.
