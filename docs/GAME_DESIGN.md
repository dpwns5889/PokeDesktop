## 1. 개요

### 1.1 한 줄 소개
작업하는 동안 화면 구석(기본 우하단)에 떠 있는 작은 창에서 일정 시간마다 야생 포켓몬이 나타나고, **과녁을 클릭하는 짧은 전투**로 포켓몬을 잡아 모으고, 잡은 포켓몬을 원정에 보내 아이템과 재화를 얻는 **방치형 데스크탑 컴패니언**.

### 1.2 핵심 경험
1. **방해하지 않는다** — 평소에는 작고 조용하다. 알림 팝업 없이 소리로만 알린다.
2. **가끔 반갑다** — 일정 시간마다 포켓몬이 나타나고, 수십 초짜리 클릭 전투로 잡는다.
3. **모으는 재미가 쌓인다** — 플레이어 레벨과 도감이 늘면서 새 지역이 열리고, 새 포켓몬과 전설의 포켓몬을 만난다.
4. **놀리지 않는다** — 잡은 포켓몬은 원정을 보내 시간만 지나면 아이템을 벌어 온다(앱을 꺼 둔 동안에도 진행). 중복 개체는 박사에게 보내 성장 자원으로 바꾼다.

### 1.3 두 가지 활동의 구분
| | 인카운터 전투 | 원정 |
|---|---|---|
| 성격 | **전투**. 나타나는 과녁을 클릭하는 짧은 액션 | **전투 아님**. 파티를 보내고 시간만 소모 |
| 소요 | 수십 초 | 5분 ~ 8시간 |
| 플레이어 조작 | 필요(클릭) | 편성·출발·수령만 |
| 결과 | 포켓몬 포획 | 아이템·재화·경험치 |

### 1.4 참고작과 참고 포인트
| 참고작 | 가져올 것 | 가져오지 않을 것 |
|---|---|---|
| **Cornerpond** | 화면 구석에 붙는 가로로 긴 작은 창, 픽셀 아트 장면, 작업 방해 최소화, **나타나는 과녁을 클릭해 게이지를 채우는 방식**, 수집/업그레이드 루프 | 아트·UI 레이아웃의 직접 복제, 낚시 소재 |
| **팰월드** | 원정(파티 편성 → 요구 전투력 → 실제 시간 → 보상), **개체마다 무작위로 붙는 특성(패시브)과 전설 특성** | 기지/작업 시스템 |
| **포켓몬 GO** | 중복 개체를 박사에게 보내 보상을 받고 레벨업에 사용 | 위치 기반 요소, 계열별 사탕(경험사탕으로 대체) |

참고는 **구조와 사용감**만 한다. 화면 구성과 UI 명칭은 직접 만든다.

### 1.5 버전 범위
- **v0.1**: 창(우하단·always on top·드래그·배율), 인카운터 전투(과녁 포획), 1세대 151종, 보관함/도감, 플레이어 레벨, 지역 해금, 전설 출현과 특성, 아이템(볼 3종·경험사탕 2종·진화의 돌), 재화·상점, 원정, 박사 보내기·레벨업, 진화, 세이브.
- **v0.2**: 사운드 전체(BGM/효과음), 색이 다른 포켓몬. (지닌 물건은 v0.24에서 폐기: 포켓몬은 아이템을 지닐 수 없다. 트레이 아이콘·시작 프로그램 등록은 M11에서 하지 않기로 함.)

## 2. 기술 환경과 프로젝트 설정

### 2.1 기본 원칙
- GDScript, **정적 타입 사용**(`var hp: int`, `func f() -> void`).
- 데이터(포켓몬·지역·원정·아이템·특성)는 코드와 분리해 `Resource(.tres)`로 관리한다(→ [7장](#7-데이터-설계와-세대-확장)).
- 상시 실행 앱이므로 **CPU/GPU 사용량을 최소화**한다.

### 2.2 기준 해상도: **448 × 200** (v0.10에서 320×120 → 320×200, **v0.46에서 448×200**)
| 근거 | 내용 |
|---|---|
| 가로 구성 (v0.46) | **왼쪽 320 = 기존 UI**(버튼 줄·장면·HUD·패널·확인 창) + **오른쪽 128 = 전투 칸**(발판·야생 포켓몬·말풍선·이름·게이지·과녁). 패널·확인 창이 전투를 가리지 않는다 |
| 세로 구성 | 위 버튼 줄 18 + 장면 163 + 아래 HUD 19 = 200 (v0.14에서 HUD 16 → 19) |
| 스프라이트 | HGSS 전투 스프라이트 80×80이 장면 안에 여유 있게 들어감 |
| 패널 | 도감·상점 등 화면을 메인 창 안의 패널로 띄우므로(6.2), 목록·버튼이 들어갈 세로 공간이 필요 |
| 폰트 | 한 줄 16px `pokemon-dppt.ttf` |
| 배율 | 정수배만 허용(1×~4×). 2× = 896×400, 3× = 1344×600 (v0.46) |
| 기본 배율 | **1×(448×200)** (v0.23. 이전에는 화면 세로에 따라 자동). 설정의 "자동"을 고르면 화면 세로 1440 이상 3×, 1080 이상 2×, 그 미만 1×. 사용자 선택값 저장 |

### 2.5 폰트: `Assets/Fonts/pokemon-dppt.ttf` — **사용 가능**
파일을 확인한 결과:
| 항목 | 결과 |
|---|---|
| 한글 완성형 | **2,355자** (KS X 1001 완성형 범위) |
| 한글 자모 | 33자 |
| ASCII | 85자 |

- KS X 1001 완성형은 일상 한글 대부분과 1세대 포켓몬 한국어 이름을 표시할 수 있다. 다만 일부 드문 글자(예: 똠, 쀍)는 없다.
- **대비책**:
  - 데이터 검증 테스트에서 게임에 쓰이는 모든 문자열(포켓몬·지역·아이템·특성 이름, UI 문구)의 글자가 폰트에 있는지 확인한다. 없는 글자가 있으면 테스트 실패.
  - 폰트에 없는 기호(확인됨): `∞`, `[`, `]` — UI 문구에 쓰지 않는다(폰트 검사 테스트가 잡아낸다).
  - **대체 폰트는 쓰지 않는다**(v0.44 결정). 화면에 나오는 글자는 모두 이 폰트에 있어야 하며, 폰트 글자 검사 테스트(`tests/data/font_glyph_test.gd`)가 데이터·스크립트의 문자열을 확인한다.
- **언어: 한국어 전용.** 게임에 표시되는 모든 텍스트(포켓몬 이름 포함)는 한국어다. 다국어 지원(Godot 번역 시스템)은 지금 하지 않는다.
- 픽셀 폰트 임포트 설정: Antialiasing **끔**, Hinting **None**, Subpixel Positioning **Disabled**, Generate Mipmaps 끔.
- 폰트 크기는 폰트의 기본 픽셀 크기 **16px**(M0에서 확인: unitsPerEm 2048 / 픽셀 격자 128)의 정수배만 쓴다. 다른 크기는 글자가 뭉개진다.
- 적용: `Assets/UI/main_theme.tres`(기본 폰트 + 크기 16)를 `gui/theme/custom`으로 지정.
- 임포트 옵션 `allow_system_fallback` 은 켜 둔다(만약 빠진 글자가 생겨도 빈칸 대신 시스템 폰트로 보이게 하는 안전장치일 뿐, 대체 폰트를 지정하지는 않는다).
- 폰트 라이선스(팬메이드 폰트로 보임)는 배포 전에 확인한다.

### 2.6 테스트 프레임워크: **gdUnit4**
| 기준 | gdUnit4 | GUT |
|---|---|---|

## 3. 창 동작

### 3.1 요구사항
| 기능 | 우선 | 내용 |
|---|---|---|
| 기본 위치: 우하단 | P0 | 실행할 때마다 작업표시줄을 제외한 영역(usable rect)의 **오른쪽 아래**에 붙는다 (v0.12에서 좌하단 → 우하단) |
| Always on top 옵션 | P0 | 설정에서 켜고 끔, 값 저장 |
| 드래그 이동 | P0 | 창 배경을 드래그해 옮김. **v0.60부터 설정의 "창 옮기기"가 켜져 있을 때만**(꺼져 있으면 잡아도 움직이지 않음, 켜면 배경 위 커서가 이동 모양, 이 설정은 저장하지 않아 실행할 때마다 꺼짐). **옮긴 위치는 저장하지 않는다** — 실행할 때마다 기본 위치(주 모니터 우하단)에 연다 (v0.11) |
| 위치 초기화 | P0 | 설정 패널 "우하단으로 되돌리기" |
| 배율 조정 | P0 | 1×~4× 정수배(비율 유지). 설정 패널 "창 크기" 또는 Ctrl+마우스 휠. 배율을 바꿀 때 오른쪽 아래 모서리를 고정 |
| 테스트 실행 크기 | P0 | 개발(디버그) 빌드는 저장된 배율과 관계없이 **2×(640×400)으로 시작**. 실행 인자 `-- --window-scale=N`으로 바꿀 수 있다. 내보낸 exe는 저장된 배율(기본 1× = 320×200) |
| 화면 이탈 방지 | P0 | 해상도/모니터 변경으로 창이 화면 밖이면 기본 위치(우하단)로 되돌림 |
| 멀티 모니터 | P2 | 다른 모니터로 이동 허용, 위치는 모니터 번호와 함께 저장 |
| 트레이 아이콘 | — | **하지 않는다**(M11 결정). 창은 X(종료 확인 후 종료)로만 닫는다 |
| 투명 배경 | P3 | per-pixel 투명 |
| 투명 영역 클릭 통과 | P3 | `DisplayServer.window_set_mouse_passthrough(polygon)` |

v0.1의 창은 **불투명한 직사각형**(지역 배경 장면이 꽉 차게 그려짐)이다.

**M1 구현 메모 (확정 동작)**
- 드래그: 배경을 누르면 `Window.start_drag()`(OS 드래그, 4.7.2에서 확인). 끝난 위치는 1초 주기 감시로 감지하지만 저장하지 않는다(v0.11). 이전 버전이 settings.cfg에 남긴 위치 값은 시작할 때 지운다.
- 도킹: 기본 위치(우하단)에서 12px 이내에 놓으면 기본 위치에 붙는다. 도킹 상태는 해상도·작업표시줄이 바뀌어도 새 기본 위치를 따라간다.
- 화면 판정: 창과 **가장 많이 겹치는** 모니터 기준. 일부만 벗어나면 그 모니터 안으로 밀어 넣고, 어느 모니터와도 겹치지 않으면 주 모니터 기본 위치로 복귀.
- 화면이 작아져 현재 배율이 안 들어가면 배율을 자동으로 낮춘다(설정값은 유지).
- 조작: 위 버튼 줄 오른쪽 **톱니바퀴 = 설정 패널**(항상 위에 표시 / 창 크기 / 우하단으로 되돌리기 / 소리), **X = 종료(확인 창, M11)**, **Ctrl+휠** = 배율. **우클릭 = 개발용 메뉴**(디버그 빌드만).
- 계산은 `scripts/logic/window_layout.gd`(테스트 대상), 상태·OS 연동은 `WindowManager`.

### 3.2 구현 방식
```gdscript
# WindowManager (오토로드)
const BASE_SIZE := Vector2i(320, 120)

func snap_to_bottom_left(screen: int = DisplayServer.window_get_current_screen()) -> void:
    var usable: Rect2i = DisplayServer.screen_get_usable_rect(screen)  # 작업표시줄 제외
    var win := get_window()
    win.position = Vector2i(usable.position.x, usable.end.y - win.size.y)

func set_always_on_top(enabled: bool) -> void:
    get_window().always_on_top = enabled
    for w in _popup_windows: w.always_on_top = enabled
    Settings.set_value(&"always_on_top", enabled)

func set_scale(factor: int) -> void:                  # 1~4
    var win := get_window()
    var bottom_left := Vector2i(win.position.x, win.position.y + win.size.y)
    win.size = BASE_SIZE * factor
    win.position = Vector2i(bottom_left.x, bottom_left.y - win.size.y)  # 왼쪽 아래 기준으로 커짐
    _clamp_into_screen()

func _on_background_gui_input(e: InputEvent) -> void:
    if e is InputEventMouseButton and e.button_index == MOUSE_BUTTON_LEFT and e.pressed:
        get_window().start_drag()   # 4.7.2에 없으면 마우스 이동량으로 position 직접 갱신
```
- 실행 순서: 설정 로드 → 배율 적용 → 저장된 위치 복원(없거나 화면 밖이면 `snap_to_bottom_left()`) → always on top 적용.
- 드래그 종료 시 위치 저장. 과녁·포켓몬·버튼 위에서는 드래그가 시작되지 않는다.

### 3.3 포커스
- 다른 앱의 키보드 포커스를 빼앗지 않는다. 인카운터가 떠도 `grab_focus`/`move_to_foreground`를 호출하지 않는다.

### 4.2 인카운터

**흐름**
```
대기 ─타이머 만료→ 출현(소리 재생) ─90초 안에 포켓몬 클릭→ 인카운터 전투(4.3)
                          └─90초 초과→ 도망
  → 결과 표시 → 대기, 다음 타이머 시작

※ 선택한 볼이 몬스터볼이 아니고 소유량 0이면: 타이머 정지(4.2 부재·볼 부족 표 참고)
```

**타이머**
- 다음 인카운터까지 = **지역별 [최소, 최대] 범위에서 고르게 뽑는다** (v0.24, 이전에는 모든 지역 6분 ±2분). 초반 지역은 짧게, 뒤 지역일수록 길게.
  - 값은 `data/source/regions_gen1.json` 의 `interval`(초) → `RegionData.encounter_interval`. 없으면 기본 4~8분, 어떤 지역도 10분(`MAX_ENCOUNTER_INTERVAL_SEC`)을 넘지 않는다.
  - 지역을 바꿨을 때 남은 시간이 새 지역의 최대 간격보다 길면 새 지역 기준으로 다시 뽑는다.

| 지역 | 초원 | 숲 | 물가 | 동굴 | 발전소 | 화산 | 유령탑 | 설산 | 깊은 동굴 |
|---|---|---|---|---|---|---|---|---|---|
| 간격 | 30초~2분 | 45초~2분 30초 | 1분 40초~3분 20초 | 2분 30초~4분 30초 | 3분 20초~5분 40초 | 4~6분 40초 | 4분 40초~7분 40초 | 5분 20초~8분 40초 | 6~9분 40초 |
- v0.53: **물가부터 최소 간격을 올리고**(최대도 조금) 뒤 지역일수록 더 오래 걸리게 했다(이전: 물가 1~3분 … 깊은 동굴 4~9분). 시뮬레이터 9.3 목표 통과(3일차 89.2종, 14일차 148.0종).
- 타이머는 "남은 시간"으로 관리하고, 실행 중에는 타임스탬프(`next_at`)로 비교한다.

**부재·볼 부족 처리**
| 상황 | 동작 |
|---|---|
| 프로그램 켜짐 + 사용자 부재 | 타이머는 흐르고 인카운터도 발생한다. **자동 포획은 없다.** 90초 안에 반응하지 않으면 도망 |
| 선택한 볼이 몬스터볼이 아니고 소유량 0 | **타이머 정지.** 남은 시간을 저장해 두고, HUD에 "볼 부족" 경고. 몬스터볼을 선택하거나 상점 구매 등으로 해당 볼 보유량이 1 이상이 되면 남은 시간부터 **재개** |
| 프로그램 꺼짐 | 인카운터는 쌓이지 않는다. **원정 시간만 흐른다.** 재실행 시 타이머를 새로 뽑는다 |

- 볼은 전투 시작 시 1개 소모하므로, 마지막 1개를 쓴 뒤 다음 타이머부터 정지된다.

**M3 구현 메모 (확정 동작)**
- 상태: `WAITING`(타이머) ⇄ `PAUSED`(볼 부족) → `PREVIEW`(바닥 발판이 떨림 2.5초 + 알림음, v0.37 이전은 풀숲) → `APPEARED`(90초) → `BATTLE` → `RESULT`(2.5초) → `WAITING`. `EncounterManager`가 상태를 갖고 화면은 `EventBus` 시그널로만 갱신한다.
- 시간은 시스템 시각으로 비교한다(테스트는 `tick(now)`에 가짜 시각).
- 출현 계산은 `EncounterLogic`, 전투 규칙은 `CaptureGame`(둘 다 순수 로직, 테스트 대상).
- 첫 지역 `data/regions/grassland.tres`(초원): 피죤·꼬렛 25, 깨비참·캐터피·뿔충이 12, 니드런♀♂ 6, 푸린·나옹 4, 피카츄 2(플레이어 Lv3부터).
- **임시 처리**: 알림음은 코드로 합성한 2음 차임(`AudioManager`), 풀숲·땅은 도형 그래픽(v0.37: 풀숲은 지역 바닥 발판으로 바뀜), 볼 배율은 `Formulas.BALL_MODIFIERS`(M6에서 ItemData로 이동), 포획 개체는 메모리에만 저장(M4에서 세이브).
- **개발용 기능** (디버그 빌드에서만): 실행 인자 `-- --fast-encounter`(간격 약 12초), `-- --autoplay`(자동으로 전투 시작·과녁 클릭, 반응 시간 0.25초), `-- --open=dex|storage|region|bag|shop`(시작하자마자 해당 패널), 우클릭 개발용 메뉴 "지금 인카운터", "돈 +10,000원", "저장 초기화..."(확인 창을 거쳐 save.json·백업·손상 보관 파일을 지우고 새 게임 상태로. 설정 settings.cfg는 유지).

**출현 포켓몬 결정**
1. 현재 지역의 출현 테이블을 가져온다.
2. `min_player_level`을 만족하는 항목만 남긴다.
3. 전설 출현 판정(4.5)을 먼저 하고, 아니면 가중치(`weight`) 랜덤으로 1종 선택.
4. 레벨 결정:
   ```
   base  = randi_range(entry.min_level, entry.max_level)
   level = clamp(base + floor(player_level * region.level_scale), entry.min_level, region.level_cap)
   ```
5. 성별 결정: 종의 `gender_ratio`(수컷 비율, 무성 = -1)로 결정. 암수 스프라이트가 다른 종은 성별에 맞는 스프라이트를 쓴다.
6. 색이 다른 개체 (**M11**): **1/512** (`Formulas.SHINY_CHANCE`, 전설도 같은 확률).
   - 전투 스프라이트는 색이 다른 버전(시트의 3·4열)을 쓴다. 오버월드(엔트리 표시)는 시트에 색이 다른 버전이 없어 일반 색.
   - 등장 연출: 문구 "색이 다른 야생 ○○ Lv5 나타났다!", 포켓몬 주변에 별 모양 반짝임이 퍼진다(`scenes/main/shiny_sparkle.gd`, 약 1.3초). 전투 중 이름 줄·포획 문구에도 "색이 다른".
   - 잡으면 개체에 `shiny: true` 와 **고정 특성 "색이다른"**(원정 전투력 ×1.2, 원정 보상 ×1.2, 4.6). 진화해도 유지. 보관함 정보에 금색 "색이 다른".
   - 등장할 때 전용 효과음 `ShinyPokemon.mp3`(5장, v0.30).
   - 개발용: 실행 인자 `-- --shiny` 면 모든 야생이 색이 다른 포켓몬(디버그 빌드만).
- **희귀도 등급은 없다.** 등장 빈도는 지역 테이블의 가중치로만 정한다.
- 시간대/날씨 출현 차이는 **미구현**. 이후 추가할 수 있게 `EncounterEntry.conditions` 자리만 둔다.

### 4.3 인카운터 전투 (과녁 클릭 포획)

인카운터는 **짧은 시간을 소모하는 전투**다. Cornerpond처럼 **나타나는 과녁을 클릭해 게이지를 채우면** 포획한다.

```
┌────────────────────────────────────────┐
│        ◎              (과녁)             │
│            [포켓몬 80×80]      ◎         │   과녁: 무작위 위치에 나타나 점점 줄어듦
│   ◎        ═══받침═══                    │   클릭 성공 → 게이지 증가
│ [■■■■■■□□□□] 12s                         │   놓침/소멸 → 게이지 감소
└────────────────────────────────────────┘
```
1. 출현한 포켓몬을 클릭하면 전투 시작. **이 시점에 선택된 볼 1개 소모**(몬스터볼은 소모 없음).
2. 과녁이 포켓몬 주변 무작위 위치에 나타나 일정 시간 동안 줄어들다 사라진다. 동시에 최대 2~3개.
3. 과녁 클릭: 게이지 +`fill`. 중심(작은 원)에 가까울수록 추가 보너스.
4. 과녁 소멸(놓침) 또는 빈 곳 클릭: 게이지 −`penalty`. 게이지는 시간이 지나면서 조금씩 줄어든다.
5. 제한 시간(**12초**, v0.55 — 이전 20초) 안에 게이지가 가득 차면 **포획 성공**(볼 던지기 연출). 실패하면 도망.
6. **포획 연출 (v0.50, `scenes/main/capture_anim.gd`)**: 게이지가 가득 차면 과녁·게이지를 치우고(왼쪽 안내 문구 "가랏! <볼 이름>!") —

   - **흔들리다 빠져나오는 실패는 없다**(게이지를 채우면 언제나 잡힘). 볼은 다음 대기 화면이 될 때까지 발판 위에 남는다.
   - 볼 그림: `Poke Balls` 시트의 볼 종류별 줄(`tools/make_ball_frames.py` → `Assets/Generated/ui/balls/<볼 id>.png`, 16×24 칸 10개: 회전 0~7(0 = 똑바로 선 모습, 놓인 볼·흔들림에 씀), 8 납작(바닥에 부딪힌 모습, 쓰지 않음 — v0.50에서 이걸 써서 볼이 가로로 찌그러져 보였음), 열림 9). 몬스터볼·슈퍼볼·하이퍼볼·마스터볼.
   - 효과음은 아직 없다(던지기·흔들림 소리를 넣으면 연결 가능). 포획 효과음은 기존대로 포획 시점에 난다.

**난이도 공식 (초안, `formulas.gd`)**
```
difficulty  = clamp((1 - catch_rate / 255.0) * 0.8 + (level / 100.0) * 0.2, 0, 1)
              (+ 0.15 전설)
target_life = lerp(1.6, 0.55, 0.6·d + 0.4·d²)   # 초. 어려운 쪽에서 더 급격히 빨라짐 (M4 조정)
target_size = lerp(17, 9, difficulty)            # 기준 해상도 px 반지름 (M4: 약간 작게)
fill        = 0.12 * ball.catch_modifier    # 게이지 비율
penalty     = lerp(0.04, 0.10, difficulty)
decay/sec   = lerp(0.01, 0.04, difficulty)
```
- 볼 배율: 몬스터볼 1.0, 슈퍼볼 1.5, 하이퍼볼 2.0.
- **과녁은 포켓몬을 가리지 않는다**: 포켓몬 스프라이트의 실제 그림 영역(투명 여백 제외)과 게이지 줄을 피해서 생성한다(과녁 원 전체가 영역 밖).
- 창 배율과 관계없이 같은 난이도가 되도록 기준 해상도 좌표로 계산한다.
- **엔트리 보너스 (v0.26, 4.13)**: 엔트리의 능력치에 따라 게이지 증가량·과녁 유지 시간·제한 시간이 늘고 감점·게이지 감소가 줄어든다(각 최대 25%).
- 볼 선택: HUD의 볼 아이콘 클릭으로 순환 선택, 선택은 저장.
- 연출 리소스: 받침은 `Battle Bases` 시트, 볼은 `Poke Balls` 시트 사용(7.4).

### 4.4 지역과 해금
- 해금된 지역 중 **하나를 현재 지역으로 선택**한다. 인카운터는 현재 지역 테이블을 쓴다.
- 지역마다 배경 장면과 전투 받침이 다르다.
- **해금 조건**은 아래 조건 타입의 조합(AND)으로 데이터에 정의한다.

| 조건 타입 | 예시 |
|---|---|
| `player_level` | 플레이어 레벨 10 이상 |
| `dex_caught_count` | 도감 포획 종류 수 20 이상 |
| `species_caught` | 특정 종 포획 |
| `type_caught_count` | 물 타입 5종 이상 포획 |
| `region_unlocked` | 이전 지역 해금 |

- 조건 확인 시점: 포획·진화·레벨업·원정 보상 수령 직후, 앱 시작 시.
- 잠긴 지역은 조건과 진행도를 보여준다.

**M5 구현 메모**
- 지역 정의는 `data/source/regions_gen1.json`(출현 표: 도감번호, 가중치, 레벨 범위, 필요 플레이어 Lv) → `tools/json_to_regions.gd` → `data/regions/*.tres`. 지역별 임시 배경색(하늘·땅)도 여기서 정한다.
- 해금 판정은 `UnlockManager`: 포획·플레이어 레벨업·앱 시작 때 확인하고, 새로 해금되면 메인 창에 "새 지역 해금: ○○!"와 알림음.
- **해금 알림 팝업 (v0.25)**: 새 지역이 열리면 "새 지역 해금" 팝업(확인 버튼 하나, `ConfirmPanel.notify`)에 "새로운 지역이 해금되었다! / 지역 이름 / 지역 버튼에서 이동할 수 있다."를 띄운다. 인카운터 대기 중에만 띄우고(전투·결과 표시 중이면 끝난 뒤), 한꺼번에 여러 지역이 열리면 한 팝업에 모은다. "확인"을 눌러야 사라진다(전투가 시작돼 닫혀도 끝난 뒤 다시 뜬다).
- 지역 선택은 버튼 줄의 "지역" 패널. 잠긴 지역은 조건별 진행도(예: `도감 10종 포획 (4/10)`)를 보여준다. 지역을 바꾸면 다음 인카운터부터 적용.
- 데이터 검증 테스트: 모든 비전설 종이 어떤 지역 표에 있거나 진화로 얻을 수 있는지, 각 지역의 해금 조건을 앞선 지역(+진화)만으로 달성할 수 있는지(막힘 방지).

### 4.5 전설의 포켓몬
- 1세대 대상: 프리져, 썬더, 파이어, 뮤츠, 뮤(환상).
- 일반 출현 테이블에 넣지 않는다. **조건을 만족하면 인카운터마다 낮은 확률(**3%**, M10. 초안 1%)로 등장.**
- **중복 포획 가능.** 잡은 뒤에도 같은 확률로 다시 나온다.
- 조건은 **자동 생성**한다(`tools/generate_legendary_conditions.gd`).
  ```
  for legend in GameData.legendaries():            # is_legendary 또는 is_mythical
      main_type  = legend.types[0]
      conditions = [
        {type: "player_level",      value: 25 + 3 * legend_index},          # 최대 37 (상한 40 이내)
        {type: "type_caught_count", type_id: main_type, value: ceil(같은 타입 비전설 종 수 * 0.6)},
        {type: "dex_caught_count",  value: floor(비전설 종 수 * 비율)},     # 비율: 일반 0.7, 뮤츠 0.9, 환상 1.0
      ]
      region_ids = main_type이 대표 타입인 지역 (없으면 모든 지역)
  ```
  다른 세대를 추가해도 같은 규칙으로 조건이 만들어진다. 결과는 `.tres`로 저장되고 손으로 고칠 수 있다.
- 전투 난이도 +0.15.

**자동 생성 결과 (1세대)**
| 전설 | 등장 지역 | 레벨 | 플레이어 Lv | 타입 포획 | 도감 포획 |
|---|---|---|---|---|---|
| 프리져 | 설산 | 50 | 25 | 얼음 3종 | 102 |
| 썬더 | 발전소 | 50 | 28 | 전기 5종 | 102 |
| 파이어 | 화산 | 50 | 31 | 불꽃 7종 | 102 |
| 뮤츠 | 유령탑 | 70 | 34 | 에스퍼 8종 | 131 |
| 뮤 | 유령탑 | 30 | 37 | 에스퍼 8종 | 146 (비전설 전체) |
- 등장 레벨 규칙: 일반 전설 50, 종족값 합 680 이상 70, 환상 30. 뮤츠 판정(0.9 비율)도 "종족값 합 680 이상"으로 자동 판단한다.
- 전설은 포획 시 고정 특성 `legend`(`data/traits/legend.tres`, 이름 "전설")를 개체에 저장한다. 개편안(4.6)의 효과: 전투력 ×1.5, 원정 보상 ×1.3(제안).
- 전설이 나타나면 메인 창에 "전설의 포켓몬!" 문구.

### 4.6 특성 (팰월드식 패시브)
- 특성은 **패시브**다. 특성마다 발동하는 곳이 정해져 있다: **원정** 특성은 그 포켓몬이 원정 파티에 있을 때, **전투** 특성은 그 포켓몬이 엔트리(4.13)일 때 발동한다. (v0.26. 이전에는 원정에만 영향)
- **모든 포켓몬은 포획 시 특성이 무작위로 생성될 수 있다**(팰월드의 개체별 패시브처럼). 같은 종이라도 개체마다 특성이 달라서, 중복 개체를 골라 키우는 이유가 된다.
- 전설·환상 포켓몬은 무작위 특성에 더해 **고정 특성 "전설"** 을 항상 가진다. 색이 다른 포켓몬(4.2, P2)은 **고정 특성 "색이다른"** 을 가진다.

> **v0.28 특성 개편 — 구현됨.** 아래 "개편 특성 목록"대로 동작한다. 개편 원칙:
> 1. M7에서 만든 기존 특성(튼튼함·힘셈·길잡이 등 16종)은 **모두 삭제**한다.
> 2. 공격·특공 같은 **개별 능력치를 바꾸는 특성은 만들지 않는다**(`stat_mult` 폐지).
> 3. **전투력을 바꾸는 효과는 자신에게만** 적용한다(파티 전원의 전투력을 바꾸는 특성은 없다, v0.26).
> 4. **실제 포켓몬 특성의 이름**을 쓴다(고정 특성 "전설"·"색이다른"은 예외).
>
> 데이터: `data/source/traits.json`(수치는 여기만 고친다) → `tools/json_to_traits_expeditions.gd` → `data/traits/*.tres`. 계산: 원정 `ExpeditionLogic`(`pokemon_power`·`party_mods`·`roll_rewards`), 전투 `BattleTraits`(`collect`·`roll_after_battle`·`buff_lines`).
> **옛 특성(튼튼함·길잡이 등)이 있던 세이브**는 불러올 때 그 특성을 지운다(지금 데이터에 없는 특성 id 제거). 고정 특성 "전설"은 id(`legend`)가 같아 그대로 남는다.
> **제안값은 모두 채택**(v0.28): 전설 보상 ×1.3, 타입 조건 전투력 ×1.2, 악취 = 전투 특성, 꿀모으기 레벨×2원, 픽업 15%, 출현 ×1.5, 중첩X·상한. 바꾸려면 JSON 만 고친다.

**특성 생성 규칙**
| 항목 | 내용 |
|---|---|
| 생성 시점 | 포획 시 1회. 이후 바뀌지 않음(진화해도 유지) |
| 개수 | 0~3개, 0/1/2/3개 = **60/25/12/3** (v0.54, 이전 50/35/12/3) |
| 등급 | 일반 / 희귀 / 전설(전설 포켓몬 전용, 무작위로는 안 나옴) / 부정(단점이 있는 특성) |
| 등급 확률 | 일반/희귀/부정 = 70/15/15 (M10 확정, 개편 후 다시 확인) |
| 중복 | 한 개체에 같은 특성 중복 불가, 서로 배타적인 특성(아래 "같이 안 붙음")은 같이 붙지 않음 |
| 표시 | 포획 결과, 보관함 목록 아이콘, 상세 화면. 등급별 색상 |
| 필터 | 보관함에서 특성으로 필터·정렬 (박사에게 보낼 개체를 고를 때 사용, 미구현) |

**개편 특성 목록 (v0.28 구현, 49종 + 보류 1)**

- **발동**: 원정 = 원정 파티에 있을 때 / 전투 = 엔트리일 때(4.13).
- **범위**: 자신 = 그 포켓몬의 전투력만 / 원정 전체 = 그 원정의 시간·보상·성공 확률 / 엔트리 = 엔트리에 있으면 전투마다.
- **중첩X**: 같은 특성을 가진 포켓몬이 원정 파티(또는 엔트리)에 여러 마리여도 1번만 적용. 다른 특성끼리는 곱한다.
- 출처: 기획 = 사용자 아이디어, 추가 = 같은 틀로 보탠 특성. 수치에 `→`가 있으면 검토 후 바꾸자고 제안한 값.
- 표 글자 색(HTML): 좋은 특성 = 파랑, 부정 특성 = 빨강.
- 원정지 이름은 4.10 기준. 타입은 1세대 기준 15종(7.2).

**밸런스 검토 (v0.26)**
1. **전투력 특성은 이제 모두 자신에게만** 적용된다. 최대 인원이 없어서 전투력 특성은 사실상 "필요 인원을 몇 마리 줄여 주는" 효과이고 후반에는 영향이 작다(v0.25 검토와 같음). 타입 조건 특성(맹화 등)은 자신만 바꾸게 되면서 ×1.1 → ×1.2로 올렸다. 무작위로 붙으므로 **그 타입이 아닌 포켓몬에 붙으면 효과가 없다**(예: 피카츄의 맹화) → 그런 개체는 박사에게 보내는 후보가 된다.
2. **원정 효과(시간·보상)는 같은 특성끼리 중첩X**, 다른 특성끼리 곱하고 상한을 둔다: 원정 시간 ×0.6~×1.3, 원정 보상(요구치 초과 보너스 ×1.5 포함) 최대 ×2.0.
3. **전설의 보상 ×1.5 → ×1.3 제안**(v0.25 검토와 같음: 후반 원정에 거의 항상 붙고, 요구치 초과 보너스와 곱하면 ×2.25).
4. **엔트리 3칸이라 전투 특성은 골라 쓰는 재미가 있다.** 엔트리로 정한 포켓몬은 원정에 못 가므로, 좋은 원정 특성을 가진 포켓몬과 전투 특성을 가진 포켓몬을 나눠 쓰게 된다. 단, 엔트리는 능력치 보너스(4.13)도 주므로 "강한 포켓몬"과 "전투 특성을 가진 포켓몬" 사이에서도 고민이 생긴다.
5. **꿀모으기 수치 주의.** 초원은 인카운터가 30초~2분마다라 시간당 전투가 30~40번까지 나온다. `야생 레벨 × 2`원이면 초원(Lv2~8)에서 시간당 약 300~600원, 깊은 동굴(Lv40~60, 4~9분 간격)에서 시간당 약 900~1,500원. 8시간 원정 재화(2,400~4,000원)와 비교하면 꽤 크다 → 구현 후 시뮬레이터로 보고 `× 1`원까지 낮출 수 있다.
6. **픽업 15%**: 시간당 전투 30번이면 아이템 4~5개. 대부분 몬스터볼·슈퍼볼로 두고, 금구슬은 낮은 가중치(예: 5%)로 둔다.
7. **출현 ↑ ×1.5**: 예를 들어 숲에서 풀 타입 가중치 합이 전체의 약 30%라면 약 39%로 오른다. 원하는 종을 노릴 수 있지만 확정은 아니다. 엔트리 3칸에 같은 특성 3개를 넣어도 중첩X라서 ×1.5 그대로.
8. **의기양양(레벨 +2)**: 포획 난이도에서 레벨 비중은 20%라 체감 난이도는 거의 같고, 포획 경험치는 레벨당 2 오른다(4.1). 지역 최고 레벨 제한이 있어 후반 지역에서는 의미가 작다.
9. **볼줍기**: v0.56부터 성공·실패 상관없이 30% 확률로 볼을 돌려준다(슈퍼볼·하이퍼볼을 평균 약 30% 아낌). 일반 등급으로 적당.
10. **부정 전투 특성(긴장감·악취)**: 엔트리에서 빼면 끝이라 부담이 작다. 부정 특성은 대부분 "그 자리에 안 쓰면 된다"이므로 이 정도가 적당하다.
11. **다크오라**는 1세대에 악 타입이 없어 보류(2세대부터). **색이다른**은 M11에서 연결했다(색이 다른 개체를 잡으면 붙음).

**효과 종류 (구현 시)**
- 원정: `power_mult`(자신, `when` 조건), `ignore_weak_type`, `weak_type_mult`, `duration_mult`, `reward_mult`, `success_bonus`, `bonus_item_chance`. 폐지: `stat_mult`, `party_power_mult`, `type_power_mult`(→ `power_mult` + `when: {self_types: [...]}` 또는 `when: {expeditions: [...]}`).
- 전투: `encounter_type_weight`(타입, 배율), `encounter_interval_mult`, `wild_level_add`, `battle_fill_mult`, `after_battle_item`(픽업), `after_battle_currency`(꿀모으기), `refund_ball`(볼줍기, chance 0.3 — v0.56, 이전 `refund_ball_on_fail`).
- 각 특성에 `trigger: "expedition" | "battle"` 를 둔다. 조건은 `when` 필드: `{kind: "power_mult", value: 1.2, when: {expeditions: ["snow_climb"]}}`.
- 중첩·상한 규칙(검토 2번)은 `formulas.gd` 한 곳에서 처리한다.

- 특성 목록(이름, 등급, 효과 종류)은 `data/source/traits.json` → `tools/json_to_traits_expeditions.gd` → `data/traits/*.tres`.
- **특성 표시 (v0.12, 팰월드의 패시브 표시 참고)**: 보관함에서 포켓몬을 고르면 오른쪽 정보에 특성마다 상자(`scenes/ui/trait_badge.gd`)가 나온다.
  - 좋은 특성: 위쪽 화살표 ^ (일반 1개, 희귀 2개, 전설 3개). 테두리·화살표 색(v0.54): **일반 = 회색**, 희귀 = 파랑, **전설 = 주황→노랑 그라데이션**(배경은 어두운 황갈색)
  - 나쁜 특성: 빨간 테두리 + 아래쪽 화살표 v
  - 마우스를 올리면 설명. 원정 편성 목록에서는 특성이 있는 개체에 `*`.
- 특성 효과는 원정 계산(4.10)과 엔트리 전투(4.13)에 반영된다. 능력치(4.7.1)는 바꾸지 않는다(v0.28).

### 4.7 보유 포켓몬

#### 4.7.1 능력치
종족값·레벨·**개체치**(v0.55)로 계산한다. 노력치는 없다.
```
hp   = floor((2 * base.hp + iv.hp) * level / 100) + level + 10
기타 = floor((2 * base.X  + iv.X ) * level / 100) + 5
최종 = floor(능력치 * Π(특성의 stat_mult))   # 특성 개편(4.6) 후 stat_mult 는 없어진다. 지닌 물건 없음(v0.24 폐기)
```

**개체치 (v0.55)**: 잡을 때 능력치 6종마다 0~31을 고르게 뽑아 개체에 저장한다(`ivs`). 같은 종·같은 레벨이어도 능력치가 다르다. 진화해도 그대로.
- 보관함 표시: **31 = 값 옆 ★★**, 25~30 = ★, 0~9 = **값이 하늘색**, 10~24 = 표시 없음.
- v0.55 이전 세이브의 개체는 불러올 때 개체치를 새로 뽑는다(범위 밖 값은 0~31로 자름).
- 엔트리 보너스 기준(4.13)은 **개체치 31**(종족값 80·Lv80) → 최대 보너스에는 개체치도 높아야 한다(개체치 노가다). 원정 전투력도 개체치가 반영된 능력치를 쓴다.

#### 4.7.2 보관함
- 개체 단위 보관: 종, 레벨, 경험치, 성별, 색이 다른 개체 여부, 특성 목록, 포획 일시·지역, 닉네임, 잠금, 상태(대기/원정 중).
- **보관 상한 기본 100마리.** 재화로 확장(초안: +20칸씩, 비용 증가, 최대 300). 가득 차면 인카운터는 발생하지만 전투 시작 전에 "보관함 가득" 안내(박사에게 보내기로 연결).
- 잠금(즐겨찾기): 박사 보내기 일괄 선택에서 제외.
- **M4 구현**: 도감(발견/포획 수/최초 포획 시각)과 보관함은 `PlayerState`, 화면은 버튼 줄의 "도감"(`dex_panel.gd`: 미발견 ?, 발견만 실루엣, 포획)과 "보관함"(`storage_panel.gd`: 정렬·능력치 상세) 패널(6.2).

### 4.8 박사에게 보내기 / 포켓몬 레벨업

#### 4.8.1 경험치 곡선
- **포켓몬 최대 레벨 100. 플레이어 레벨과 무관하게** 올릴 수 있다.
```
exp_to_next(L)  = 50 + 10 * L + floor(L * L / 2)
total_exp(L)    = Σ exp_to_next(1 .. L-1)        # Lv1에서 Lv L까지 필요한 누적 경험치
```
| 레벨 | 다음 레벨까지 | 누적(Lv1부터) |
|---|---|---|
| 5 | 112 | 약 320 |
| 10 | 200 | 약 1,000 |
| 20 | 450 | 약 4,100 |
| 30 | 800 | 약 10,100 |
| 50 | 1,800 | 약 34,900 |
| 100 | — | 약 218,600 |

> 위 누적값은 공식으로 계산해 `formulas.gd`의 테스트로 고정한다. 표는 참고용이다.

#### 4.8.2 박사에게 보내기
- 포켓몬 GO 방식. 놓아주기 기능은 박사에게 보내기로 대체한다.
- 개체를 보내면 사라지고 **보낸 포켓몬의 레벨에 비례한 경험사탕**을 받는다. 별도 자원은 없다.
- 지급량 계산 (자동, `formulas.gd`):
  ```
  value   = 100 + floor(total_exp(level) * 0.18)   # 경험치 환산값: 키운 경험치의 18% + 기본 100 (M10, 초안 25%)
  M 개수  = floor(value / 800)
  S 개수  = round((value - M * 800) / 100)         # 최소 1개 보장
  ```
  | 보낸 레벨 | 환산값 | 받는 사탕 |
  |---|---|---|
  | 5 | 약 180 | S×2 |
  | 10 | 약 350 | S×4 |
  | 20 | 약 1,130 | M×1, S×3 |
  | 30 | 약 2,620 | M×3, S×2 |
  | 50 | 약 8,830 | M×11 |
  | 100 | 약 54,750 | M×68, S×4 |
- 18%라서 같은 경험치를 다시 쌓으려면 손해 → 키운 개체를 쉽게 보내지 않게 하면서, 막 잡은 중복 개체(저레벨)는 꾸준히 사탕이 된다. 비율(0.18)과 기본값(100)은 밸런스 상수. 위 표는 초안(25%) 기준이며 현재 값: Lv5 → S2, Lv20 → M1, Lv50 → M7 S8.
- 단일/일괄 보내기 지원(종별 "1마리만 남기고 보내기", 특성 없는 개체만 보내기 필터).
- 원정 중이거나 잠금된 개체는 보낼 수 없다.

**M8 구현 메모 (보내기)**
- `ProfessorManager.transfer(uids)`: 하나라도 보낼 수 없으면(원정 중·잠금) 아무것도 보내지 않는다. 보낸 개체의 도감 기록은 남는다.
- **중복 보내기**(보관함 제목 줄): 종마다 가장 좋은 1마리(레벨 높은 순 → 특성 많은 순)를 남기고 나머지를 보낸다. 잠금·원정 중·**특성 있는 개체는 남긴다**. 보내기 전에 마릿수와 받을 사탕을 확인 창으로 보여준다.
- **잠금**: 보관함 오른쪽 아래 "잠금/해제". 잠금된 개체는 목록에서 금색, 보낼 수 없다.

#### 4.8.3 레벨업 방법
| 방법 | 내용 |
|---|---|
| 경험사탕 | 가방에서 사용. 박사 보내기·원정·상점으로 얻음. S = +100, M = +800 |
| 원정 | 원정 완료 시 참여 포켓몬이 경험치를 얻음 |
- 넘친 경험치는 다음 레벨로 이어진다.
- **M8 구현**: 보관함에서 포켓몬을 고르고 오른쪽 아래 사탕 버튼(아이콘 + 개수)을 누른다. **왼쪽 클릭 = 1개, 오른쪽 클릭 = 다음 레벨까지 필요한 만큼**(작은 S부터 쓰고, 모자라면 M 1개). 원정 중이거나 Lv100이면 쓸 수 없다. 가방에서 경험사탕을 고르면 "보관함에서 주기"로 보관함 패널을 연다.

### 4.9 진화 (**P1** — 원정 등 기초 시스템 완료 후)

| 진화 방식 | 처리 |
|---|---|
| 레벨 | **진화 레벨에 도달하는 즉시 진화 연출 시작**. 사탕·재화 소모 없음 |
| 진화의 돌 | 가방에서 돌을 사용(확인 창) → 진화. 돌 1개 소모 |
| 이브이 | 사용한 돌(불꽃/물/천둥)에 따라 분기 |
| 통신교환 → **레벨로 대체** | 아래 표 |

**통신교환 진화 대체 (같은 계열 3단 진화와 비슷한 레벨)**
| 진화 전 | 진화 후 | 대체 조건 | 참고 |
|---|---|---|---|
| 윤겔라 | 후딘 | Lv36 | 캐이시→윤겔라 Lv16, 3단 스타팅과 동일한 36 |
| 근육몬 | 괴력몬 | Lv40 | 알통몬→근육몬 Lv28 |
| 데구리 | 딱구리 | Lv40 | 꼬마돌→데구리 Lv25 |
| 고우스트 | 팬텀 | Lv38 | 고오스→고우스트 Lv25 |

**진화 취소**
- 레벨 진화 연출 중 "취소" 버튼으로 멈출 수 있다(본가의 B 버튼처럼).
- 취소하면 **다음 레벨업 때 다시 진화를 시도**한다.
- 취소한 개체는 상세 화면에 "진화하기" 버튼이 생긴다(Lv100이라 더 레벨업할 수 없는 경우 등에 대비).
- 일괄 처리 중(사탕 여러 번 사용, 원정 귀환 등) 여러 마리가 진화하면 연출을 순서대로 하나씩 보여준다.
- 원정 중 진화 레벨에 도달하면 **귀환 시** 진화 연출.
- 진화하면 도감에 새 종이 포획으로 등록되고 플레이어 경험치를 얻는다. 특성·성별·색이 다른 개체 여부는 유지.

**M9 구현 메모**
- `EvolutionManager`: 진화 대기열(한 번에 하나씩 연출), 확인/취소, 레벨·돌 조건 확인.
- **레벨 진화**: 경험사탕·원정 보상 등으로 진화 레벨에 도달하는 순간 대기열에 들어가 연출이 시작된다. 취소하면 다음 레벨업 때 다시 시도하고, 그 전에도 보관함의 **"진화하기"** 버튼으로 다시 진화할 수 있다(Lv100이거나 앱을 껐다 켠 경우 대비).
- **진화의 돌**: 보관함에서 포켓몬을 고르면 가진 돌 중 쓸 수 있는 것만 버튼(아이콘 + 이름)으로 나온다. 돌은 연출이 끝나 진화가 확정될 때 소모(취소하면 돌은 그대로). 가방에서 돌을 고르면 "보관함에서 쓰기".
- **연출** (`scenes/ui/evolution_overlay.gd`): 버튼 줄·장면을 덮고(HUD는 보임) "어라...? ○○의 모습이...!" → 진화 전/후 모습이 점점 빠르게 번갈아 빛남(이때 "취소") → "○○는(은) ○○(으)로 진화했다!" + "확인". 다음 진화가 기다리고 있으면 확인 뒤 이어서 보여준다.
- 진화하면 도감에 포획으로 등록, 플레이어 경험치 `20 + 신규 도감 40`(M10). 특성·성별·레벨·색이 다른 개체 여부 유지. 이미 다음 단계 레벨도 넘었으면 이어서 진화(예: Lv40 이상해씨 → 이상해풀 → 이상해꽃).
- 원정 중인 개체는 진화하지 않는다. 원정 보상으로 레벨이 오르면 귀환 처리 뒤라 바로 진화 연출.
- 테스트: 1세대 진화 경로 전부(레벨·돌·통신 대체·이브이 분기)를 실제로 진화시켜 확인.

### 4.10 원정 (전투 아님)

- 포켓몬 경험치: 원정 보상 경험치로 레벨업(최대 100, 4.8.1 곡선). 진화는 M9.

**흐름 (팰월드 원정 구조 참고)**
```
원정지 선택 → 파티 편성(5마리 이상, 자동 선택 가능) → 전투력 확인(요구치 대비) → 출발
  → 실제 시간 경과(앱 종료 중에도 진행) → 귀환 → 보상 수령
```
- 원정은 **시간만 소모**한다. 전투 연출이나 조작은 없다. 결과는 전투력 비교로만 정해진다.

**규칙**
- 파티 **5마리 이상, 최대 인원 없음** (v0.24, 이전 4~6마리). 원정 중인 포켓몬은 다른 원정·박사 보내기·진화·레벨업·엔트리 불가. **엔트리(4.13)는 원정에 보낼 수 없다**(편성 목록·자동 선택에서 빠짐).
- **자동 선택** (v0.24, `ExpeditionLogic.auto_select`): 원정 중이 아닌 포켓몬을 이 원정지 기준 전투력 높은 순으로 넣되, 5마리를 채우고 요구치(100%)를 넘는 순간 멈춘다 → 성공 100%가 되는 가장 적은 파티. 끝까지 넣어도 못 넘으면 전부 고른다(성공 확률은 화면에 표시). 편성 화면의 "자동 선택" 버튼. 고른 뒤 직접 더하거나 뺄 수 있다.
- 인원 제한이 없으므로 **요구 전투력을 v0.23의 3배로 올렸다**(아래 원정지 표). 시뮬레이션(9.2)에서 자동 선택 인원은 평균 약 11마리(5~24마리).

| 원정지 | 시간 | 요구 전투력 (v0.23 → v0.24) |
|---|---|---|
| 초원 산책 | **5분** (v0.32, 이전 30분) | 200 → **600** |
| 숲 탐험 | **15분** (v0.32, 이전 1시간) | 450 → **1,350** |
| 물가 낚시 | **30분** (v0.32, 이전 1시간) | 700 → **2,100** |
| 동굴 발굴 | **1시간** (v0.32, 이전 2시간) | 1,000 → **3,000** |
| 발전소 순찰 | 2시간 | 1,400 → **4,200** |
| 화산 조사 | 4시간 | 1,900 → **5,700** |
| 유령탑의 밤 | 4시간 | 2,300 → **6,900** |
| 설산 등반 | 8시간 | 2,800 → **8,400** |
| 깊은 동굴 원정 | 8시간 | 3,600 → **10,800** |

- 동시 진행 원정 수: 1개로 시작, 플레이어 Lv15에 2개, Lv30에 3개(M7 구현).
- 소요 시간: 원정지별 고정. v0.32: 초원 산책 5분 / 숲 탐험 15분 / 물가 낚시 30분 / 동굴 발굴 1시간 / 발전소 순찰 2시간 / 화산 조사·유령탑의 밤 4시간 / 설산 등반·깊은 동굴 원정 8시간. 보상(재화·아이템·경험치)은 시간을 줄이기 전 값 그대로라 초반 원정은 시간당 보상이 크다.
- 시작 시각을 Unix 타임스탬프로 저장하고 `Time.get_unix_time_from_system()`과 비교 → 앱이 꺼져 있어도 진행. 시계를 되돌려 음수가 되면 0으로 처리.
- 원정 취소: 가능, 보상 없음.
- 원정지도 해금 조건을 가진다(4.4와 같은 조건 타입).

**전투력 계산 (초안)**
```
개체 전투력 = (최종 HP + 공격 + 방어 + 특공 + 특방 + 스피드) * type_bonus
  최종 능력치 = 4.7.1 (stat_mult 특성 포함)
  × 자신의 power_mult, type_power_mult 특성   # 특성 개편(4.6) 후에도 유지 (+ ignore_weak_type, weak_type_mult)
  type_bonus = 원정지 추천 타입과 일치하면 1.25 (복합 타입은 하나만 일치해도) / 불리 타입이면 0.85

파티 전투력 = Σ 개체 전투력 * party_bonus
  party_bonus = 1.0 + (서로 다른 타입 수 ≥ 4 ? 0.05 : 0)   # 인원 보너스는 v0.24에서 없앰 (인원 제한이 없으므로)
              × 파티의 party_power_mult 특성   # 개편 후: 타입별 배율(party_type_power_mult), 같은 특성은 중첩X

소요 시간 = 기본 시간 × 파티의 duration_mult 특성 (하한 있음)
보상     = 추첨 횟수 + reward_rolls_add, 재화 × currency_mult, 경험치 × exp_mult
```

**결과**
- `ratio = 파티 전투력 / 요구 전투력`
- `ratio ≥ 1.0`: 성공. 초과분에 비례해 보상 보너스(상한 1.5배).
- `0.7 ≤ ratio < 1.0`: 성공 확률 `(ratio - 0.7) / 0.3`. 실패 시 보상 30%.
- `ratio < 0.7`: 출발 불가(UI에서 막음).
- 공통: 참여 포켓몬 경험치, 플레이어 경험치.

**보상**
- 원정지별 보상 테이블(아이템 ID, 수량 범위, 가중치)에서 N회 추첨 + 재화.
- 보상 종류: **재화, 볼, 경험사탕, 진화의 돌**. 열쇠 아이템·지닌 물건은 없다.
- 원정지마다 주는 진화의 돌을 다르게 한다(화산 → 불꽃의 돌).

| 묶음 | 엔트리 능력치 | 전투 효과 (4.3 파라미터) |
|---|---|---|
| 공격 | 공격 + 특공 | 명중 시 게이지 증가량 `fill` × (1 + 보너스) |
| 스피드 | 스피드 | 과녁 유지 시간 `target_life` × (1 + 보너스) |
| 방어 | 방어 + 특방 | 빗나감 감점 `penalty`, 게이지 감소 `decay_per_sec` × (1 − 보너스) |
| HP | HP | 제한 시간 `time_limit` × (1 + 보너스) |
```
기준   = 종족값이 모두 80인 Lv80 포켓몬의 능력치 (HP 218, 나머지 133)       # 1세대 최종 진화 평균 종족값 ≈ 80
r      = 엔트리 3칸의 능력치 합 / (기준 × 3)     # 빈 칸은 0, 1에서 자름
보너스 = 0.25 × r^1.5                             # 낮은 레벨에서 더 작게
```
| 엔트리 3마리 (종족값 80 기준) | Lv10 | Lv20 | Lv40 | Lv60 | Lv80 | Lv100 |
|---|---|---|---|---|---|---|
| 보너스 | 약 2% | 약 4% | 약 9% | 약 16% | **25% (최대)** | 25% |
- v0.26(야생과 비교, 같은 능력치면 +12.5%)은 초반에 너무 쉽게 최대가 되어 바꿨다. 이제 **Lv80 3마리**를 키워야 최대에 닿는다.
- 종족값이 높은 종(예: 망나뇽·뮤츠, 평균 100 이상)은 Lv65 안팎에서 최대, 낮은 종(평균 60)은 Lv100이어도 약 23%. → **종족값이 높은 개체를 골라 오래 키우는 육성**이 필요하다. (v0.55부터 개체치(4.7.1)가 있어 같은 종·레벨이어도 차이 나고, 최대 보너스 기준도 개체치 31이다.)
- 1마리만 Lv80이면 r = 1/3 → 약 4.8%. 3칸을 모두 채워야 효과가 크다.
- **보너스만 있고 손해는 없다** → 엔트리가 없으면 v0.25와 같은 전투.
- 시뮬레이터(9.2)의 가상 플레이어는 하루 끝에 능력치가 가장 높은 3마리를 엔트리로 둔다(엔트리는 원정·진화 후보 원정 동행에서 빠짐). v0.28 결과(10회 평균, 특성 개편 포함): 1일차 Lv13.0·51.3종, 3일차 Lv21.9·95.5종, 7일차 Lv36.4·136.4종, 10일차 Lv40·145.5종, 14일차 Lv40·149.2종 → 9.3 목표 모두 통과. 14일차 소지금 약 5.1만 원(v0.27 4.4만), 전설 6.9마리. 가상 플레이어는 특성을 보고 엔트리를 고르지 않는다(능력치만).

**파티 패널** (`scenes/ui/party_panel.gd`, 버튼 줄 "도감"과 "보관함" 사이 "파티")
- 제목 줄 "파티 · 엔트리 n/3". 왼쪽 = 엔트리 3칸(빈 칸은 "(빈 자리)") + "빼기" + 전투 보너스 두 줄(예: "게이지 +9%  과녁 +9% / 감점 -9%  시간 +9%"; 마우스를 올리면 설명). 오른쪽 = 넣을 수 있는 포켓몬(원정 중·엔트리 제외, 레벨 순) + "넣기". 목록을 두 번 누르면 바로 넣고 뺀다.
- 보관함 목록에서 엔트리는 연두색, 정보에 "엔트리" 표시.
- **메인 화면 (6.1)**: 장면 오른쪽 아래(v0.59)에 엔트리의 **오버월드 앞모습**(32×32 걷기 2프레임, v0.28. 누르면 파티 패널, 마우스를 올리면 이름·레벨), 오른쪽 위에 엔트리로 받는 버프 목록(능력치 보너스 + 전투 특성).

(보상 30%)"(빨강). 위 = "획득한 아이템" 칸들, 구분선, 아래 = "포켓몬 경험치 +N"과 레벨이 오른 포켓몬 칸들(없으면 "레벨이 오른 포켓몬은 없다"). **칸** = 36×36 사각형(테두리 1px) 안 위 가운데에 그림(아이템 아이콘 / 포켓몬 오버월드 아이콘 / 돈은 직접 그린 동전), **아래 가운데에 획득량**(돈 "2,350", 아이템 "×3", 포켓몬 연두색 "+2"), 마우스를 올리면 이름(포켓몬은 "이름 Lv 전 → 후"). 칸이 많으면 줄바꿈. 아이템·포켓몬 영역은 좌우 10px 여백. 가운데 "확인" 버튼으로만 닫는다(닫기 버튼 숨김). 내용이 길면 스크롤. 편성 화면 = 왼쪽 포켓몬 목록(여러 개 선택, 전투력 순) / 오른쪽 원정지·추천 타입, "전투력 현재/요구 (비율)"·"인원 · 성공 확률 · 시간" 두 줄, 자동 선택, 뒤로·출발.
- **확인** (`confirm_panel.gd`): 되돌릴 수 없는 동작 확인(예: 개발용 저장 초기화).

## 7. 데이터 설계와 세대 확장

### 7.1 원칙
- **세대는 데이터로만 추가한다.** 코드에 "151", "1세대" 같은 상수를 넣지 않는다.
- 포켓몬 기본 키는 **전국도감 번호**.
- 세대별 데이터는 폴더로 분리하고, 시작 시 레지스트리가 폴더를 스캔해 로드한다.
- 활성 세대는 데이터로 제어한다(`enabled_generations: [1]`). 2세대 스프라이트 시트가 이미 있으므로, 2세대 추가 시 **시트 영역 정의 + CSV만 추가하면 되는지**를 확장성 검증 기준으로 삼는다.
- 전설 조건 생성, 도감 크기, 타입 목록은 활성 세대 데이터에서 계산한다.

### 7.2 Resource 정의
```gdscript
class_name PokemonSpecies extends Resource
@export var dex_id: int                    # 전국도감 번호 (키)
@export var generation: int
@export var name_ko: String
@export var name_en: String               # UI에 표시하지 않음. 스프라이트 시트·PokeAPI 데이터와 맞추는 용도
@export var types: Array[StringName]       # [&"grass", &"poison"]
@export var base_stats: Dictionary         # {hp, atk, def, spa, spd, spe}
@export var catch_rate: int                # 0–255 (전투 난이도)
@export var base_exp: int
@export var gender_ratio: float            # 수컷 비율 0.0~1.0, 무성 = -1
@export var has_gender_sprites: bool       # 암수 스프라이트가 다른 종
@export var evo_stage: int                 # 0=기본, 1, 2
@export var is_legendary: bool
@export var is_mythical: bool
@export var fixed_trait_ids: Array[StringName] = []   # 항상 붙는 특성. 전설: [&"legend"]. 무작위 특성은 개체에 저장
@export var evolutions: Array[Dictionary]
    # [{to: 2, method: "level", value: 16}]
    # [{to: 136, method: "item", item: "fire_stone"}]
    # 통신 대체: [{to: 65, method: "level", value: 36}]
# 스프라이트는 리소스에 연결하지 않는다 → PokemonSprites가 경로 규칙
#   res://Assets/Generated/sprites/gen<N>/<dex 4자리>.png 로 필요할 때 불러온다(없으면 플레이스홀더).
#   저장소에 스프라이트가 없어도 데이터가 깨지지 않고, 필요한 종만 메모리에 올라간다.
# 희귀도 필드는 두지 않는다.

class_name EncounterEntry extends Resource
@export var dex_id: int
@export var weight: int
@export var min_level: int
@export var max_level: int
@export var min_player_level: int = 1
@export var conditions: Array[Dictionary] = []   # 예약: 이후 시간대/날씨

class_name RegionData extends Resource
@export var id: StringName
@export var name_ko: String
@export var main_types: Array[StringName]
@export var background: PackedScene
@export var battle_base: Texture2D
@export var encounters: Array[EncounterEntry]
@export var level_scale: float = 0.2
@export var level_cap: int
@export var unlock_conditions: Array[Dictionary]

class_name LegendaryRule extends Resource         # 자동 생성 결과
@export var dex_id: int
@export var chance: float = 0.01
@export var region_ids: Array[StringName]         # 빈 배열 = 모든 지역
@export var conditions: Array[Dictionary]

class_name TraitData extends Resource
@export var id: StringName
@export var name_ko: String
@export var description: String
@export var tier: StringName                      # normal / rare / legend / negative
@export var weight: int = 10                      # 무작위 생성 가중치 (legend 등급은 0 = 무작위로 안 나옴)
@export var effects: Array[Dictionary]            # [{kind: "duration_mult", value: 0.9}] — 4.6 효과 종류
@export var exclusive_with: Array[StringName]     # 같이 붙을 수 없는 특성

class_name TraitRollConfig extends Resource      # 특성 생성 규칙 (data/traits/roll_config.tres)
@export var count_weights: Array[int]             # [0개, 1개, 2개, 3개] 가중치 (60/25/12/3, v0.54)
@export var tier_weights: Dictionary              # {normal: 70, rare: 15, negative: 15}

class_name ExpeditionData extends Resource
@export var id: StringName
@export var name_ko: String
@export var duration_sec: int
@export var required_power: int
@export var min_party: int = 4
@export var max_party: int = 6
@export var recommended_types: Array[StringName]
@export var weak_types: Array[StringName]
@export var reward_table: Array[Dictionary]       # [{item: "great_ball", min: 1, max: 3, weight: 10}]
@export var reward_rolls: int = 3
@export var currency_reward: Vector2i
@export var exp_reward: int
@export var unlock_conditions: Array[Dictionary]

class_name ItemData extends Resource
@export var id: StringName
@export var name_ko: String
@export var category: StringName      # ball / exp_candy / evolution
@export var params: Dictionary        # {catch_modifier: 1.5} / {exp: 100}
@export var sources: Array[StringName]  # [&"shop", &"expedition"]
@export var buy_price: int = 0        # 0 = 상점 판매 안 함
@export var sell_price: int = 0       # 0 = 판매 불가
@export var infinite: bool = false    # 몬스터볼만 true
@export var icon: AtlasTexture
```
- 타입 한국어 이름은 `res://data/types/types.json`(`{"fire": "불꽃", …}`). 타입 상성표는 필요해질 때 `data/types/`에 추가한다.
- **타입은 1세대 기준**(M3 결정, 타입 15종 — 페어리·강철·악 없음): 삐삐·픽시·푸린·푸크린 = 노말, 마임맨 = 에스퍼, 코일·레어코일 = 전기.
  - 기준 세대는 `tools/build_species_csv.py --type-gen <N>`으로 바꾼다(0 = 현재 세대). 다른 세대를 추가할 때 이 값을 정하고 모든 세대 CSV를 다시 만든다. `types.json`은 생성된 CSV에 쓰인 타입만 담는다.
- 종족값은 현재 세대 기준(1세대의 '특수'가 특공/특방으로 나뉜 값).

  | 1줄 | 일반 | 일반 | 일반 | 일반 |

- **암수 차이가 있는 종**(예: 이상해꽃, 버터플, 피카츄, 잉어킹, 갸라도스)은 "Male"/"Female" 표시와 함께 블록이 2배 폭으로 나란히 있다. 이 블록은 머리줄이 조금 더 높다.
- 칸 배경이 투명이 아니다: 앞모습 `#93BBEC`(하늘색), 뒷모습 `#54A54B`(초록). → **임포트 시 배경색을 투명으로 바꾼다.** DS 스프라이트 색은 모두 8의 배수(0, 8, …, 248)라서 배경색과 절대 겹치지 않는다 → 같은 색 픽셀을 전부 지워도 안전하다(M2에서 확인: 남은 비-DS 색 픽셀 0개).
- 블록 머리줄 오른쪽의 작은 아이콘(높이 16px)은 칸 검출에서 걸러진다.
- 시트 끝의 "FIXED KABUTO"는 투구 **뒷모습**만 고친 블록이다. 앞모습만 쓰므로 사용하지 않는다.
- 가로는 40칸 고정 격자(블록 10개 × 4칸)라 계산으로 구하고, 세로는 머리줄 높이가 달라 검출한다.

**임포트 파이프라인 (`tools/import_battle_sprites.gd`, M2 완료)**
1. **칸 행 검출**: 각 행에서 40개 칸 열의 첫 픽셀이 배경색이면 '칸 행' → 연속 80px 묶음 = 칸 1행, 2행씩 = 블록 행(일반/색다름).
2. **블록 → 도감번호**: 읽는 순서대로 블록을 나열하고, CSV의 `has_gender_sprites`인 종은 블록 2개(수컷, 암컷)를 가져간다. 필요 수(151 + 암컷 22 = 173)와 검출 수(174, 보정판 투구 포함)를 비교해 어긋나면 실패.
3. **종별 시트 PNG**: 앞모습만 잘라 배경을 투명하게 한 뒤 `Assets/Generated/sprites/gen1/<dex>.png`에 저장.
   - 배치: 열 = [일반 프레임1, 일반 프레임2, 색다름 프레임1, 색다름 프레임2], 행 = [수컷/공통, 암컷].
   - 뒷모습은 쓰지 않는다(필요해지면 열을 추가).
4. **사용**: `PokemonSprites.make_frames(species, female, shiny)` → 2프레임 `idle` 애니메이션 SpriteFrames.
5. **검증**: 미리보기(`Assets/Generated/preview_gen1.png`, 도감 순서, 종당 [일반 | 암컷 | 색다름])로 눈 검토 + 테스트(`tests/data/sprite_assets_test.gd`).

**오버월드(필드) 스프라이트 (`tools/import_overworld.gd`, v0.28)** — 메인 화면 엔트리 표시용

### 8.3 시그널 흐름 예시

## 10. 성능·안정성 기준
- 평상시 CPU 1% 내외, 메모리 150MB 이하 목표(측정 후 조정). 1세대 전투 시트(3241×3511)는 한 장으로 로드하면 약 45MB이므로, 필요한 종만 잘라 쓰거나 생성된 종별 텍스처로 쪼개는 방식을 M2에서 비교한다.
- 평상시에는 애니메이션 프레임을 낮추고, 전투 중에만 30fps 이상.
- 모든 타이머는 프레임 누적이 아닌 **타임스탬프 비교**(절전/일시정지 후에도 정확).
- 세이브 손상 시 `.bak`에서 복구, 둘 다 실패하면 새 게임 + 손상 파일 보관.

### 10.1 Windows 빌드 (M10)
- 설정: `export_presets.cfg` 의 "Windows Desktop" (x86_64, pck를 exe 안에 포함). 결과물은 `build/PokeCompanion.exe` 하나(git 제외).
- 명령: `<godot> --headless --path . --export-release "Windows Desktop" build/PokeCompanion.exe` (내보내기 템플릿 4.7.2 필요).
- 제외: 원본 아틀라스 `Assets/Sprites/*`, `tests/*`, `tools/*`, `docs/*`, `addons/gdUnit4/*`, `data/source/*`. 게임 데이터는 약 1.6MB, BGM 15곡(v0.34). exe 크기의 대부분은 Godot 실행기와 BGM 이다.
- 릴리스 빌드에서는 우클릭 개발 메뉴, `--autoplay`, 창 2배 시작이 꺼진다. 세이브 위치는 디버그와 같다(`%APPDATA%\Godot\app_userdata\PokeProject`).

## 12. 리스크와 주의사항
- **저작권/상표**: 포켓몬의 이름·이미지는 닌텐도/게임프리크/크리처스/(주)포켓몬의 IP이고, `Assets/Sprites`의 HGSS 시트는 **게임에서 추출한 저작물**이다(시트에도 저작권 표기가 있음). 비상업 목적이라도 공개 배포하면 권리자가 삭제를 요청할 수 있다.
  - 지인 공개: 공개 링크가 아닌 개별 전달 수준으로 한정 권장.
  - 포트폴리오: **영상/GIF와 소스 코드 위주**로 공개하고, 공개 저장소에는 `Assets/Sprites/`와 `Assets/Generated/`를 넣지 않는다(`.gitignore`). 스프라이트가 없을 때는 플레이스홀더로 실행되도록 폴백을 둔다.
  - 폰트 `pokemon-dppt.ttf`도 출처와 라이선스를 확인한다.
- **always on top과 전체화면 앱**: 전체화면 게임/영상 위에 뜨는 문제 → "전체화면 앱 감지 시 숨김" 옵션 검토(P2).
- **드래그 API**: `Window.start_drag()`가 4.7.2에 없거나 다르게 동작하면 수동 드래그로 대체.
- **아틀라스 자동 검출 실패**: 블록 배치가 불규칙해 자동 검출이 일부 틀릴 수 있다 → JSON 수동 수정 + 미리보기 시트로 확인.
- **시계 조작**: 원정 시간은 시스템 시계 기준. 개인용이므로 음수 경과만 막는다.
- **Godot 4.7.2 API 차이**: 문서의 API 이름은 4.3~4.x 기준. 구현 전에 확인.
